版本：0.1.0

最後更新：2026-08-03  
重大變更摘要：建立中文四堂與英文五堂前導課程的共同授課流程、作業討論、錯誤案例、參與觀察與備援策略。  
對應英文版本：[Preparatory Course Instructor Implementation Guide](session-guides.en.md)

## 文件用途

供教師與助教直接執行前導課程。本文不定義最終口試的完整題型與流程；口試細節將另立正式文件。

## 共同授課循環

除第一堂外，每堂原則上依下列順序：

```text
前次作業討論 15–25 分鐘
→ 本堂核心問題
→ 視覺模型與執行前預測
→ 最小可執行範例
→ 引導修改、測試與除錯
→ 課堂整理
→ 指定下一份自主作業
```

作業不繳交、不計分。學生自行保存程式、測試、追蹤、錯誤與 AI 使用紀錄。

## 課堂參與觀察

可觀察證據包括：

- 提出具體問題或說明卡點。
- 回答、修正或補充推理。
- 參與程式追蹤、測試、除錯或解法比較。
- 分享自己犯過的錯誤。
- 提出正常、邊界或異常測試。
- 透過書面、匿名提問、程式操作或小組紀錄參與。

不得以出席、點名、發言次數或反應速度取代參與判定。

# 中文班四堂執行安排

## 第 1 堂：執行模型與第一個程式（180 分鐘）

### 核心問題

> 人類寫下的 C 原始碼，如何成為電腦實際執行的行為？

### 建議時間

| 時間 | 活動 |
|---:|---|
| 0–20 | 課程制度：不點名、作業不繳、課堂參與與最終口試 |
| 20–45 | 原始碼、編譯器、可執行檔與執行流程圖 |
| 45–70 | 預測並執行最小程式 |
| 70–90 | 漏分號等編譯錯誤診斷 |
| 90–100 | 休息 |
| 100–130 | 修改程式但不重新編譯的實驗 |
| 130–160 | 值、變數與第一個狀態追蹤 |
| 160–175 | 學生操作與分享錯誤 |
| 175–180 | 指定自主作業 1 |

### 必備錯誤案例

- 漏分號造成編譯失敗。
- 修改原始碼但執行舊可執行檔。
- 把「編譯成功」誤認為「程式已執行且正確」。

### 錯誤 AI 建議

> 「修改 `.c` 檔後直接執行舊的 `.exe`，作業系統會自動讀取最新原始碼。」

學生先預測，再透過修改輸出文字、執行舊檔、重新編譯三個步驟驗證。

### 時間不足時

保留工具鏈、預測、漏分號錯誤與重新編譯實驗；縮短自由練習。

## 第 2 堂：資料、型別與狀態（180 分鐘）

### 前次作業討論

優先討論：

- 編譯與執行的差異。
- 為何修改後必須重新編譯。
- 學生自行製造的錯誤。

### 核心問題

> 程式如何記住資料、改變資料，並讓我們確認結果合理？

### 建議時間

| 時間 | 活動 |
|---:|---|
| 0–25 | 作業 1 討論與匿名錯誤案例 |
| 25–55 | 值、型別、變數、初始化與指定 |
| 55–85 | 狀態追蹤表與手算 |
| 85–95 | 休息 |
| 95–125 | `scanf`、處理與輸出 |
| 125–150 | 整數除法與格式型別錯誤 |
| 150–170 | 需求修改與回歸測試 |
| 170–180 | 指定自主作業 2 |

### 必備錯誤案例

```c
int total = 5;
int count = 2;
double average = total / count;
```

另準備 `%d`、`%lf` 與變數型別不一致的案例。

### 錯誤 AI 建議

> 「只要左邊是 `double`，右邊的整數除法就一定會保留小數。」

要求學生先手算，再執行 `5 / 2` 與 `5.0 / 2` 比較。

## 第 3 堂：條件、迴圈與終止（180 分鐘）

### 前次作業討論

優先討論：

- 型別選擇。
- 狀態表與實際程式不一致的位置。
- 滿額免運等需求修改的測試。

### 核心問題

> 程式如何選擇路徑並可靠地重複工作？

### 建議時間

| 時間 | 活動 |
|---:|---|
| 0–25 | 作業 2 討論 |
| 25–55 | 條件與路徑模型 |
| 55–85 | 邊界案例與條件順序 |
| 85–95 | 休息 |
| 95–125 | 迴圈四要素與逐次追蹤 |
| 125–150 | off-by-one 與無窮迴圈診斷 |
| 150–170 | 有效成績統計器修改與測試 |
| 170–180 | 指定自主作業 3 |

### 必備錯誤案例

- 把 `=` 寫成比較用途。
- 邊界使用 `<` 而非 `<=`。
- 迴圈忘記更新控制變數。
- 結束標記也被加入統計。

### 錯誤 AI 建議

> 「迴圈只要有 `break` 就不可能成為無窮迴圈。」

要求學生找出 `break` 永遠無法執行的反例。

## 第 4 堂：函數、整合與 AI 驗證（180 分鐘）

### 前次作業討論

優先討論：

- 終止條件與更新順序。
- off-by-one 錯誤。
- 零筆有效資料的處理。

### 核心問題

> 如何把小型需求分解、實作、測試、修改並驗證 AI 建議？

### 建議時間

| 時間 | 活動 |
|---:|---|
| 0–25 | 作業 3 討論 |
| 25–55 | 函數責任與介面圖 |
| 55–85 | 呼叫、參數與回傳值追蹤 |
| 85–95 | 休息 |
| 95–130 | 重構過大的 `main` |
| 130–155 | 整合作業與需求修改 |
| 155–170 | 錯誤 AI 建議審查 |
| 170–180 | 作業整理與最終口試準備原則 |

### 必備錯誤案例

- 函數宣告回傳值但沒有 `return`。
- 呼叫端忽略回傳值。
- 函數名稱與責任不一致。
- 需求修改後只測新功能，未回歸舊功能。

### 錯誤 AI 建議

> 「將所有變數改成全域變數，可以讓函數分解更簡單，因此是初學者最好的解法。」

學生比較全域狀態與參數／回傳值的可追蹤性和測試性。

# 英文班五堂節奏對照

- Session 1：第 1 堂前半，執行模型與第一個程式。
- Session 2：資料、型別與程式狀態。
- Session 3：條件、迴圈與終止。
- Session 4：函數與責任分解。
- Session 5：整合循環、AI 驗證與作業整理。

英文班每堂 120 分鐘，除 Session 1 外同樣先保留 15–20 分鐘討論前次作業。可使用術語卡、句型支架、書面回答與成對討論，核心任務與標準不變。

## 備援環境

- 教師預先測試的 GCC／Clang C17 環境。
- 無法使用個人設備時，以教師設備、成對操作或紙上追蹤完成核心活動。
- 工具故障不得直接視為未參與或能力不足。

## 課後教師紀錄

每堂只需記錄：

- 本堂主要誤解。
- 有效的錯誤案例。
- 學生普遍卡點。
- 需要下堂延續的問題。
- 課堂參與的整體趨勢與少量代表性證據。

不得建立逐次點名表或以每次發言累積分數。
