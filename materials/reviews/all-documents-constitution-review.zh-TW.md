# 全文件憲法遵循重審

版本：1.0.0  
狀態：正式審查紀錄  
最後更新：2026-08-05  
對應英文版本：[Repository-Wide Constitution Compliance Review](all-documents-constitution-review.en.md)

## 文件目的

本文件依據 `CONSTITUTION.zh-TW.md` 重新審視目前倉庫中的正式文件，包含：

- 根 README 與主要導覽
- 設計文件 `design/01–17`
- 前導學生教材 P-U01 至 P-U04
- 正式課程學生教材 F-U01 至 F-U12
- 教材索引、模板、評量、作業與教師資源
- AI 相關文件與措辭

本次審查的目的不是只確認檔案存在，而是確認正式內容符合雙語、可發現性、獨立閱讀、Concept 先於語法、預測與驗證、錯誤教學、認知負荷、能力導向及 AI 不取代思考等憲法要求。

## 整體結論

目前文件架構已建立完整的設計鏈：

```text
課程憲法
→ 願景與需求
→ Concept Tree／Registry
→ Unit Map
→ 16 個 Unit 大綱
→ 16 個雙語學生教材
→ 作業、評量與教師資源
```

整體方向符合憲法，但在 PR #8 合併前發現並修正三類明確問題：

1. 正式課程中文版索引有三個失效連結。
2. 教材總索引仍停留在只有前導教材完成的舊工作階段，導致 12 個正式 Unit 無法從主要索引抵達。
3. 教材總索引仍把 AI 使用紀錄與驗證描述成每個 Unit 的固定要求，與目前「低比重概念對話」定位不一致。

上述問題已在 `agent/complete-remaining-15-units` 分支同步修正中英文版本。

## 一、雙語完整性

### 符合項目

- 課程憲法具有繁體中文與英文版本。
- 設計文件 `01–17` 具有雙語對應版本。
- P-U01 至 P-U04 具有中英文學生教材。
- F-U01 至 F-U12 具有中英文學生教材。
- 正式課程與教材總索引具有中英文版本。
- PR #8 的 30 份 Unit 教材完整配對，沒有單語 Unit。

### 仍需注意

雙語「檔案配對」已完成，但技術用語、程式碼、測試資料、錯誤案例與練習限制仍需要逐 Unit 的實質等值檢查。尤其 F-U05 至 F-U12 概念較複雜，不應只依賴標題與段落結構判斷等值。

## 二、文件目的與獨立閱讀

### 符合項目

- P-U01 已明確區分學生教材、教師指引與評量制度。
- P-U02 至 P-U04 及 F-U01 至 F-U12 都具文件用途、核心問題、完成標準、練習與摘要。
- 教材不再依賴教師口頭說明才能理解主要流程。
- 教師排程、課堂參與觀察與評分行政主要留在教師及評量文件中。

### 仍需注意

較複雜的正式 Unit 雖具完整結構，但目前多採「完整而精煉」寫法。仍需確認學生是否真的能獨立建立以下心智模型：

- F-U05：call frame、scope、lifetime 與 recursion
- F-U06：address、pointer、indirection 與 aliasing
- F-U08：allocation、ownership、lifetime 與 release
- F-U10：interface、implementation、translation 與 linking

## 三、教材寫作順序

### 符合項目

大部分 Unit 已依循：

```text
核心問題
→ 預測或觀察問題
→ 視覺模型
→ Concept
→ 最小程式
→ 追蹤
→ 錯誤案例
→ 練習與需求修改
→ 自我檢核與摘要
```

教材普遍先建立 Concept，再介紹 C 語法；也包含至少一個可重現錯誤案例與修正流程。

### 仍需注意

不得因統一模板而讓所有 Unit 機械地使用相同篇幅。不同 Concept 應依理解需要調整：

- 表示與型別需要位元與轉換圖。
- 指標與動態記憶體需要記憶體圖與生命週期圖。
- 模組化需要檔案、編譯與 linking 關係圖。
- 測試與除錯需要 evidence chain，而不只是程式碼範例。

## 四、預測、錯誤與驗證

### 符合項目

- P-U01 至 P-U04 都有預測、追蹤、錯誤診斷及需求修改。
- 正式 Unit 普遍有正常案例、錯誤案例、測試或回歸活動。
- 文件明確指出編譯成功、執行成功、OJ 通過或 AI 正面回應都不能單獨證明能力。

### 仍需完成

目前仍缺少全 Unit 的實際編譯驗證。所有教材程式應在指定環境中以 C17 編譯，並檢查：

- GCC 與 Clang 警告
- Linux／macOS 與 Windows 指令差異
- 預期輸入輸出
- 未定義行為與實作定義行為
- 陣列與字串邊界
- 動態記憶體錯誤
- 檔案開啟與 EOF 處理
- 多檔案 linking

在完成此技術驗證前，PR #8 應維持 Draft。

## 五、認知負荷與資訊層級

### 符合項目

- 教材以短段落、小型程式、表格與流程圖降低負荷。
- 新概念大致依 Unit Map 順序建立。
- 前導課程沒有提前要求完整理解 pointer、dynamic allocation 或 advanced data structures。

### 需要補強

憲法要求明確區分：

- 必須理解
- 必須完成
- 建議練習
- 延伸探索
- 目前可跳過

P-U01 的學生教材主要透過段落語意表達層級，正式 Unit 也未全面使用一致標籤。這不是立即阻擋問題，但在較長 Unit 中應加入資訊層級，以避免所有內容看起來同等重要。

## 六、AI 定位

### 目前正式定位

AI 不是獨立 Unit，也不是每章的主要學習活動。每個 Unit 結尾只提供簡短活動：

> 學生用自己的話向 AI 解釋核心 Concept。

不要求固定 prompt、不要求保存或繳交對話，也不把 AI 回應視為權威。若 AI 回應與程式、測試、編譯器行為或可重現結果衝突，學生仍須依證據判斷。

### 已修正問題

教材總索引原先仍要求明確的 AI 允許／禁止／保存證據與 AI 使用紀錄。這種寫法會把 AI 放大成固定課程工作，與目前設計決策不一致。現在已改為：

- AI 僅為低比重概念對話工具。
- AI use log 保留為非強制延伸資源。
- AI 不是 Unit 完成條件。

## 七、導覽與可發現性

### 已確認的導覽鏈

```text
README.md
→ materials/README.zh-TW.md 或 materials/README.en.md
→ preparatory/ 或 formal/ 教材索引
→ 各 Unit
→ 對應語言版本與前後 Unit
```

### 已修正問題

正式課程中文版索引原先有三個錯誤路徑：

- F-U02 指向 `unit-02-advanced-control.zh-TW.md`
- F-U10 指向 `unit-10-modules.zh-TW.md`
- F-U12 指向 `unit-12-integration.zh-TW.md`

實際檔名分別為：

- `unit-02-complex-control-flow.zh-TW.md`
- `unit-10-modular-programming.zh-TW.md`
- `unit-12-integrated-application.zh-TW.md`

教材總索引也已新增正式課程入口，使 12 個正式 Unit 不再是孤立文件。

## 八、評量與作業制度

### 符合項目

- 作業不繳交、不計分、不逐份批改。
- 下一堂課保留作業討論時間。
- 不以點名或出席率計分。
- 課堂參與可透過多種方式展現。
- 正式成績只由課堂參與與一次最終一對一口試構成。

### 仍需注意

根 README、教材索引、教師指引、作業包與 rubric 應持續保持相同措辭。任何舊文件若仍出現逐份通過、補驗、微型口試或強制作業提交，都應依 `design/13` 與評量制度補充規則修正。

## 九、單一內容來源與維護性

目前 Concept Tree、Registry、Unit Map、大綱與教材之間已有可追蹤關係，但雙語 Markdown 仍是兩份獨立檔案，存在長期漂移風險。

後續建議建立自動檢查：

- 每個 `.zh-TW.md` 必須有對應 `.en.md`
- Unit 標題、版本、狀態與更新日期一致
- 程式碼區塊與測試資料相同
- 交叉連結有效
- 索引列出的檔案存在
- 每個 Unit 至少具備必要章節

## 十、合併前條件

PR #8 在以下條件完成前應維持 Draft：

1. 完成 15 個新增 Unit 的技術與雙語實質抽查。
2. 至少實際編譯所有完整 C 程式範例。
3. 檢查所有 Unit 的前後導覽與對應語言連結。
4. 修正審查中發現的技術或教學問題。
5. 確認教材模板與現行教材結構一致，或明確記錄模板更新為下一個 PR。

## 審查結論

目前倉庫的課程設計方向、16-Unit 結構、雙語策略、學生教材形式、評量制度與 AI 定位，整體符合憲法。

本次重審已修正導覽與 AI 定位的明確不一致，但 PR #8 尚未完成實際 C17 編譯與逐 Unit 技術等值驗證，因此目前結論為：

> **文件架構與教學設計條件式符合；技術驗證完成前不建議合併 PR #8。**
