# 前導課程教師與助教批改指引

版本：0.1.0  
狀態：正式教師草案  
最後更新：2026-08-03  
重大變更摘要：建立作業證據檢查、口試抽查、公平判定與補驗執行流程。  
對應英文版本：[Preparatory Grading Guide for Instructors and TAs](grading-guide.en.md)

## 文件用途

供教師與助教一致執行作業批改、形成性回饋、微型口試與補驗。不得只看程式輸出或自動測試結果。

## 一、批改順序

1. 先確認需求、能力、範圍與必要證據。
2. 閱讀學生在執行前的理解、預測與測試。
3. 檢查程式是否符合目前範圍及規格。
4. 比對追蹤、預期結果與實際行為是否一致。
5. 檢查需求修改、錯誤診斷與回歸測試。
6. 有使用 AI 時檢查透明度與技術驗證。
7. 以一至三題微型口試抽查核心能力。
8. 依缺失能力決定通過、條件通過、補驗或未通過。

## 二、不得使用的捷徑

- 只看是否編譯。
- 只看 OJ 或測試通過率。
- 因程式與範例答案不同而直接扣分。
- 因英文表達不流利而降低程式能力判定。
- 看到 AI 使用就直接判不及格，或反過來完全不檢查。
- 讓總分掩蓋無法解釋、沒有測試或沒有回歸驗證的核心缺口。

## 三、微型口試原則

- 使用學生自己的程式，但替換輸入、門檻或需求。
- 問「下一步狀態是什麼」「為什麼這個測試重要」「改哪裡會影響什麼」。
- 不要求背誦語法定義。
- 不得由 AI 即時代答。
- 通常控制在 2–5 分鐘。

## 四、補驗對應

| 缺口 | 補驗方式 |
|---|---|
| 執行模型 | 分類新錯誤並畫出工具鏈 |
| 狀態理解 | 以新數值完成即時追蹤 |
| 條件／迴圈 | 找出邊界或終止錯誤並修正 |
| 函數理解 | 修改介面、追蹤參數與回傳值 |
| 測試不足 | 補正常、邊界與必要異常案例 |
| 除錯不足 | 重現、假設、驗證、修正與回歸 |
| AI 驗證不足 | 審查新的錯誤建議並附證據 |

補驗只針對缺失能力，不要求無差別重做完整作業。

## 五、雙語公平

- 中英文班使用相同 rubric、能力 ID 與通過標準。
- 英文班可使用術語卡、句型支架與較多閱讀時間。
- 中文班多出的時間用於追蹤、補救、診斷與驗收，不增加核心要求。
- 技術理解可透過圖、表、程式追蹤或簡短語句表達；不把語言華麗度當成技術成熟度。

## 六、工具故障

工具故障時：

1. 記錄環境問題。
2. 切換到備援環境。
3. 保留預測、追蹤、測試與說明活動。
4. 不因無法在原設備執行而直接判定能力不足。

## 七、AI 使用判定

有效 AI 使用應包含：

- 使用前的理解與方案。
- 學生先建立的測試。
- AI 建議摘要。
- 可重現的驗證方法。
- 採用、修改或拒絕理由。

若程式正確但學生無法解釋 AI 影響部分，安排口試與需求修改補驗，不以猜測動機取代證據。

## 八、發布成績前檢查

- [ ] 已查看理解型與行動型證據。
- [ ] 未只依賴輸出、編譯或 OJ。
- [ ] 已允許合理不同解法。
- [ ] 補驗與缺失能力直接對應。
- [ ] 中英文班標準一致。
- [ ] AI 使用依透明度與驗證判定。
- [ ] 學生安全、尊嚴與公平優先。
