# 單元教材模板

版本：1.1.0  
狀態：教材作者使用的建議模板  
最後更新：2026-08-06  
重大變更摘要：取消固定 AI 章節與機械式章節要求，改以教學目的、主要讀者與核心能力為中心；AI 僅能作為可跳過的選用延伸。  
對應英文版本：[Unit Material Template](TEMPLATE.en.md)

## 文件用途

本模板供教材作者建立學生可獨立閱讀、練習、複習與查閱的 Unit 教材。它提供建議結構與發布前檢查，不是所有 Unit 必須逐項照抄的固定格式。

教師排程、課堂觀察、評量行政、答案提示與最終口試流程應放在教師或評量文件，不混入學生章節。

正式評量規則只以 `design/13-learning-assessment-policy.*` 為準。本模板不得自行新增繳交、計分、出席、AI 紀錄或口試規則。

## 完成標準

完成一個 Unit 不只是讓程式產生輸出。學生應依該 Unit 的教學目的，能完成適當組合的能力，例如：

- 解釋核心 Concept 或心智模型。
- 預測或追蹤程式行為。
- 閱讀、修改或完成最小實作。
- 診斷代表性錯誤。
- 建立測試並處理小幅需求修改。
- 以程式、測試、編譯器行為或其他可重現證據驗證判斷。

不要求每個 Unit 同時包含所有活動；選擇應服務核心問題與認知負荷。

AI 預設為選用。未使用 AI 不影響 Unit 完成、課堂參與或評量。若提供 AI 活動，必須清楚標示為可直接跳過的選用延伸，且核心完成標準與自我檢核不得依賴 AI。

## 建議結構

以下區段依需要選用、合併或調整順序。

### 一、開始前

- 這個 Unit 要回答什麼問題？
- 學生開始前應具備什麼？
- 完成後應能做出哪些可觀察行為？
- 哪些內容目前可以跳過？

學習目標應具體可觀察，避免只使用「熟悉」或「了解」。

### 二、問題、需求或可觀察現象

先建立問題、需求、矛盾、錯誤現象或預測任務，再引入語法。

可要求學生先預測：

- 輸出
- 狀態
- 控制路徑
- 呼叫順序
- 記憶體關係
- 錯誤類型

### 三、心智模型與視覺表示

依需要使用流程圖、狀態圖、記憶體圖、關係圖、時序圖或追蹤表。

每張圖應說明：

- 要觀察什麼。
- 節點、箭頭、位置或狀態代表什麼。
- 圖如何對應程式行為。
- 如何透過追蹤、執行或測試驗證。

沒有教學價值的裝飾性圖形不必加入。

### 四、核心 Concept 與語言邏輯

可依下列脈絡組織：

```text
問題或需求
→ 心智模型
→ 核心 Concept
→ C 語法與工具
→ 程式行為
→ 驗證方式
```

使用一致術語，但不要為了內部治理把需求 ID、能力 ID、追蹤矩陣或維護 metadata 放進學生閱讀主線。

### 五、最小範例

清楚標示內容屬於：

- 完整程式
- 程式片段
- 虛擬碼
- 刻意錯誤範例

```c
/* code */
```

依需要提供：

- 預期輸入
- 預期輸出
- 編譯指令
- 執行方式
- 已驗證的工具與版本

範例只引入目前必要的新概念，不同時塞入尚未建立的技巧。

### 六、追蹤、診斷與驗證

依學習目標選擇適當活動：

| 步驟 | 敘述／條件 | 目前狀態 | 預期或觀察結果 |
|---|---|---|---|
| 1 |  |  |  |

代表性錯誤案例應包含：

- 可重現的症狀
- 可能原因
- 診斷步驟
- 修正理由
- 修正後測試
- 必要的回歸確認

不得只提供修正版答案，也不得把偶然輸出當成技術證據。

### 七、練習與需求修改

依 Unit 需要安排閱讀、預測、補完、追蹤、修改、測試或獨立實作。

任務至少說明：

- 要做什麼
- 為什麼要做
- 可使用的資源
- 限制或安全條件
- 完成標準

允許符合規格、目前範圍、安全與可讀性的不同合理解法。

測試表可依需要使用：

| 類型 | 輸入或操作 | 預期結果 | 實際結果 | 判定 |
|---|---|---|---|---|
| 正常 |  |  |  |  |
| 邊界 |  |  |  |  |
| 必要異常 |  |  |  |  |
| 回歸 |  |  |  |  |

需求修改可要求學生：

1. 指出受影響部分。
2. 更新預期結果與測試。
3. 修改程式或模型。
4. 執行回歸驗證。
5. 說明修改理由。

### 八、選用延伸

延伸活動必須和核心活動清楚區分，學生可以直接跳過。

若使用 AI，可採下列形式：

> 選用：將你已完成的解釋交給 AI，檢查它是否指出新的疑問，再以程式、編譯器、測試或可重現結果判斷其說法。

不得要求：

- 固定 Prompt。
- 特定 AI 工具。
- 保存或繳交完整對話。
- 未使用 AI 聲明。
- 把 AI 回應當成權威答案或核心能力證據。

### 九、自我檢核與摘要

自我檢核只包含核心能力，例如：

- 我能用自己的話解釋核心 Concept。
- 我能在執行前做出合理預測。
- 我能追蹤關鍵狀態或流程。
- 我能重現並診斷代表性錯誤。
- 我能建立測試並處理需求修改。

摘要應說明：

- Unit 解決了什麼問題。
- 建立了哪些能力。
- 哪些內容刻意延後。
- 下一個 Unit 如何使用這些 Concept。

## 發布前檢查

- [ ] 主要讀者、核心問題與完成標準清楚。
- [ ] 中英文版本實質等值，且各自自然可讀。
- [ ] 前置 Concept、新 Concept 與延後內容明確。
- [ ] 問題、需求或心智模型先於語法。
- [ ] 活動數量與新概念數量符合認知負荷。
- [ ] 完整程式已在指定環境實際編譯與執行。
- [ ] 程式碼、輸入、輸出與測試資料一致。
- [ ] 刻意錯誤案例已清楚標示且可安全重現。
- [ ] 不以正確輸出、編譯成功、OJ 或工具評價作為唯一能力證據。
- [ ] AI 若出現，已標示為可跳過的選用延伸。
- [ ] 核心完成標準與自我檢核不依賴 AI。
- [ ] 沒有教師排程、評分行政、答案提示或內部治理內容污染學生主線。
- [ ] 導覽與語言切換連結完整。
