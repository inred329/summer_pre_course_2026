# 正式單元 F-U01：表示、型別與運算為什麼會影響結果？

版本：1.0.1  
狀態：正式學生教材  
最後更新：2026-08-05  
對應英文版本：[Formal Unit F-U01: Why Do Representation, Type, and Operations Affect Results?](unit-01-representation-types.en.md)

## 文件用途與完成標準

本章供學生獨立閱讀、練習與複習。完成本章代表你能說明同一組位元如何因型別與解讀方式產生不同意義，能預測轉型與運算結果，並能用測試診斷溢位、整數除法、浮點誤差與格式化 I/O 型別不匹配。

## 核心問題

> 同一個數值或運算，為什麼可能因表示方式與型別而產生不同結果？

完成本章後，你應能：

1. 區分值、表示與型別。
2. 說明位元、MSB 與 LSB 的位置意義。
3. 預測整數除法、轉型與格式化輸出。
4. 說明浮點數不是所有實數的精確表示。
5. 把有號溢位與 variadic format mismatch 分類為未定義行為。
6. 用邊界案例與容許誤差測試結果。

---

## 1. 先看一組位元

```text
10110010
```

在沒有額外資訊時，它可能代表無號整數、有號整數、字元編碼的一部分，或其他格式。位元本身只有 0 與 1；型別與規則賦予它意義。

---

## 2. MSB 與 LSB

對一個固定位數的位元序列：

```text
1 0 1 1 0 0 1 0
^             ^
MSB           LSB
```

- MSB（Most Significant Bit）：權重最高、最左側的位元。
- LSB（Least Significant Bit）：權重最低、最右側的位元。

在無號二進位整數中，LSB 的權重是 1，向左每一位權重乘 2。MSB 只是位置名稱；在不同表示法中，它可能具有不同角色。

---

## 3. 型別決定解讀與可用操作

```c
unsigned int count = 10;
int change = -3;
double ratio = 0.5;
char letter = 'A';
```

型別影響可表示範圍、儲存方式、運算規則、格式化輸入輸出與轉型行為。它不只是變數前面的關鍵字，而是一組解讀與操作規則。

---

## 4. 整數除法與轉型

```c
int a = 5;
int b = 2;
double x = a / b;
double y = (double)a / b;
```

預測：

```text
x = 2.0
y = 2.5
```

`a / b` 先依兩個 `int` 做整數除法；把結果存進 `double` 不會補回已丟失的小數。顯式轉型改變運算前的型別。

---

## 5. 浮點表示與誤差

```c
#include <stdio.h>

int main(void) {
    double x = 0.1 + 0.2;
    printf("%.17f\n", x);
    return 0;
}
```

結果可能接近但不完全等於 `0.3`。許多十進位小數無法用有限二進位位數精確表示。

可使用容許誤差：

```c
#include <math.h>

if (fabs(x - 0.3) < 1e-9) {
    printf("close enough\n");
}
```

誤差門檻應由需求與數值尺度決定；`1e-9` 只是範例，不是通用常數。

---

## 6. 整數範圍與溢位

```c
#include <limits.h>

printf("%d\n", INT_MAX);
```

不要猜測固定範圍。有號整數溢位屬未定義行為，因此一次觀察結果不能當成保證。對可能溢位的加、減、乘法，應在運算前檢查邊界。

無號整數會依模數規則回繞，但只有在需求明確採用 modular arithmetic 時才是正確行為。

---

## 7. 字元也是資料表示

```c
char c = 'A';
printf("%c %d\n", c, c);
```

同一個 `char` 可依格式顯示成字元或整數碼。數值碼取決於 execution character set；除非環境或需求明確指定，不能直接假設 ASCII。

---

## 8. 錯誤案例與分類

### 儲存型別不會改變先前運算

```c
double average = total / count;
```

若需求需要小數結果，這通常是邏輯／需求錯誤。應檢查運算元型別，且在除法前拒絕 `count == 0`。

### 浮點數直接相等比較

直接相等在語法上合法，對某些可精確表示的值也可能適用；但對計算產生的近似值通常是邏輯錯誤。比較規則應由需求決定。

### Variadic 格式不匹配

```c
printf("%d\n", 3.14);
```

`%d` 要求 `printf` 取出 `int`，但 variadic argument 實際是 `double`。型別不匹配，行為未定義。編譯器警告是診斷證據；此處正確格式為 `%f`。

---

## 9. 引導練習

1. 將 8 位元 `00101101` 由 LSB 向 MSB 標出權重並計算無號值。
2. 預測 `7 / 3`、`7.0 / 3`、`(double)7 / 3`。
3. 比較 `0.1 + 0.2` 與 `0.3`，並說明採用的誤差門檻。
4. 使用 `-Wall -Wextra -Wformat=2 -pedantic` 編譯格式不匹配片段，只依診斷分類，不執行它。

---

## 10. 自主練習：資料表示報告器

檢查輸入成功後，讀入一個整數與一個浮點數，輸出整數十進位、十六進位、浮點固定小數位，以及除數非零時的浮點商。

測試正常值、非數字輸入、零除數與接近相關型別界限的值。

---

## 11. 需求修改

新增規則：若除數為零，不進行除法，而輸出 `Undefined`。先更新測試表，再修改控制流程並回歸原案例。

## 14. 本章摘要

資料的位元表示必須配合型別與規則才有意義。運算結果取決於運算元型別，轉型時機會改變結果，浮點數需要以近似規則思考，格式化 I/O 則要求格式與實際引數型別完全一致。下一章將把這些判斷放進更複雜的控制流程。
