# 正式單元 F-U06：如何透過位址間接操作資料？

版本：1.1.0  
狀態：正式學生教材  
最後更新：2026-08-09  
對應英文版本：[Formal Unit F-U06: How Can Data Be Manipulated Indirectly Through Addresses?](unit-06-pointers.en.md)

從前導課程開始，我們其實早就看過：

```c
scanf("%d", &score);
```

當時只需要先把 `&score` 理解成「讓 `scanf` 知道要把輸入寫到哪裡」。

到了 F-U03 與 F-U04，我們又刻意延後了一個問題：為什麼陣列交給函數後，函數可以存取原本的元素？

現在把這些線索放在一起：

> C 程式除了可以操作一個物件目前的值，也可以取得它的位置，保存那個位置，再透過位置回到原物件。

這就是位址與指標模型。

---

## 1. 先把「物件、值、位址」分成三件事

```c
int score = 80;
```

`score` 是一個 `int` 物件，目前保存的值是 80。

除了讀值：

```c
printf("%d\n", score);
```

還可以取得這個物件的位址：

```c
&score
```

現在宣告一個能保存 `int` 物件位址的變數：

```c
int *p = &score;
```

概念圖：

```text
p ──────► score
          value: 80
```

可以把四個東西清楚分開：

- `score`：物件名稱。
- `80`：目前值。
- `&score`：`score` 的位址。
- `p`：一個指標物件，保存這個位址。

指標本身也有自己的值；只是它的值用來表示另一個物件的位置。

---

## 2. `&` 取得位置，`*` 透過位置回到物件

有：

```c
int score = 80;
int *p = &score;
```

則：

```c
printf("%d\n", *p);
```

`*p` 表示：使用 `p` 保存的位址，存取那個位置上的 `int` 物件。

所以會讀到 80。

更重要的是，它也可以出現在指定運算左邊：

```c
*p = 90;
```

這不是把 `p` 本身改成 90，而是透過 `p` 找到 `score`，再把 `score` 改成 90。

追蹤：

```text
p 保存 &score
→ *p 表示 score 這個物件
→ *p = 90
→ score 的值變成 90
```

這就是「間接存取」：不是直接用 `score` 名稱，而是先透過另一個值找到它。

---

## 3. 現在回頭看 `scanf(..., &score)`

```c
int score;
scanf("%d", &score);
```

`scanf` 要修改呼叫者的 `score`，所以不能只拿到 `score` 當時的值；它需要知道要把轉換結果寫進哪一個物件。

`&score` 就提供那個位置。

這也解釋了為什麼：

```c
scanf("%d", score);
```

不是「少打一個符號而已」。`%d` 對應的引數需要提供可寫入 `int` 的位置；直接給 `score` 的整數值並不符合這個介面契約。

---

## 4. 指標參數讓函數修改呼叫者的物件

例如：

```c
#include <limits.h>
#include <stddef.h>

int add_bonus(int *score, int bonus) {
    if (score == NULL) {
        return 0;
    }

    if ((bonus > 0 && *score > INT_MAX - bonus) ||
        (bonus < 0 && *score < INT_MIN - bonus)) {
        return 0;
    }

    *score += bonus;
    return 1;
}
```

呼叫：

```c
int value = 80;

if (add_bonus(&value, 5)) {
    printf("%d\n", value);
}
```

流程是：

```text
main 有 value
→ 傳入 &value
→ score 參數保存 value 的位址
→ *score 就是呼叫者的 value
→ *score += 5
→ main 的 value 變成 85
```

這就是前面一直延後到現在才正式建立的「輸出／修改參數」模型。

同時別忘了 F-U01：既然要做加法，仍要在真正運算以前確認結果可表示。指標不會讓溢位規則消失。

---

## 5. `NULL` 表示「目前沒有指向可解參照的物件」

可以寫：

```c
int *p = NULL;
```

這時 `p` 是一個 null pointer。

它可以被檢查：

```c
if (p != NULL) {
    printf("%d\n", *p);
}
```

但不能直接：

```c
printf("%d\n", *p);
```

當 `p == NULL` 時，沒有可由這個指標合法解參照的 `int` 物件；解參照 null pointer 屬未定義行為。

所以一個接受指標的函數首先要把規則說清楚：

> 這個參數允不允許 `NULL`？如果允許，`NULL` 代表什麼？如果不允許，誰負責保證？

`add_bonus` 選擇「允許收到 `NULL`，但回傳失敗且不解參照」。這是一種介面設計，不是所有函數唯一的設計。

---

## 6. 指標有效性不只看它是不是 `NULL`

看這個函數：

```c
int *bad_pointer(void) {
    int local = 10;
    return &local;
}
```

`&local` 在 `local` 還活著時確實是它的位址。

但是 F-U05 已經建立：一般自動區域物件的生命週期會在這次呼叫結束時結束。

所以函數回傳後，先前那個位址不能再被當成「仍然存在的 `local` 物件」來解參照。

這類指標常被稱為 **dangling pointer**。

重要的是：

> 指標裡的位址數字「看起來還是一樣」不代表原本的物件仍在生命週期內。

因此有效指標至少要同時問：它是不是指向一個現在仍存在、而且你有權依目前操作存取的物件？

---

## 7. 兩個不同指標可以找到同一個物件

```c
int value = 10;
int *a = &value;
int *b = &value;
```

此時：

```text
a ──┐
    ├──► value
b ──┘
```

`a` 與 `b` 是同一物件的兩個 **aliases（別名）**。

如果：

```c
*a = 20;
```

那 `*b` 也會讀到 20，因為它們不是兩份資料，而是兩條找到同一物件的路。

這會影響函數設計。

例如：

```c
#include <stddef.h>

int swap(int *a, int *b) {
    if (a == NULL || b == NULL) {
        return 0;
    }

    int temporary = *a;
    *a = *b;
    *b = temporary;
    return 1;
}
```

若呼叫：

```c
swap(&value, &value);
```

兩個參數指向同一物件。這個實作仍然合法，只是最後值不變，形成 no-op。

其他函數可能不允許兩個輸出參數指向同一物件；重點不是「aliasing 一律不好」，而是介面必須知道自己是否允許它。

---

## 8. 現在正式回答：為什麼陣列參數和指標關係這麼近？

有：

```c
int values[3] = {10, 20, 30};
```

在大多數運算式中，陣列表達式 `values` 會轉成指向第一個元素的指標，也就是效果上對應：

```c
&values[0]
```

所以：

```c
int *p = values;
```

會讓 `p` 指向第一個元素。

```text
p
│
v
+----+----+----+
| 10 | 20 | 30 |
+----+----+----+
  0    1    2
```

因此：

```c
*p        /* 10 */
*(p + 1)  /* 20 */
*(p + 2)  /* 30 */
```

`p + 1` 不是「位址數字加 1 byte」的意思，而是移動到下一個 `int` 元素的位置。

---

## 9. One-past 指標可以形成，但不能解參照

對長度 3 的 `values`：

```c
int *begin = values;
int *end = values + 3;
```

`end` 指向最後一個元素之後一格的位置。

這個 **one-past pointer** 可以用來比較與控制走訪：

```c
for (int *p = begin; p != end; p++) {
    printf("%d\n", *p);
}
```

每次真正解參照的 `p` 都還是 0、1、2 那三個元素。

當 `p == end` 時迴圈停止，不會執行 `*p`。

所以：

```c
int *end = values + 3;   /* 可以形成 */
```

和：

```c
printf("%d\n", *end);  /* 不可以解參照 */
```

是兩件不同的事。

指標算術也不是任意位址算術；它的有效範圍和所屬陣列物件有關。不要把指標當成可以隨便加減的整數。

---

## 10. 把常見指標錯誤放回四個問題

看到 `*p` 以前，可以先固定問：

1. **初始化了嗎？** `p` 現在真的有一個可用的指標值嗎？
2. **是 `NULL` 嗎？** 這個介面允許嗎？
3. **目標還活著嗎？** 指向的物件仍在生命週期內嗎？
4. **位置在合法邊界內嗎？** 如果來自陣列，現在是元素位置還是 one-past？

例如：

```c
int *p;
*p = 10;
```

`p` 沒有先取得一個可合法解參照的目標。

```c
int *p = NULL;
*p = 10;
```

目標明確不存在。

```c
int *p = bad_pointer();
*p = 10;
```

曾經指向的區域物件生命週期已結束。

```c
int values[3] = {10, 20, 30};
int *p = values + 3;
printf("%d\n", *p);
```

位置是合法形成的 one-past，但不是可解參照元素。

這四個問題比背「野指標、空指標、懸空指標」名詞更有用。

---

## 11. 自主練習：一次找出最小值與最大值

現在指標已經正式建立，可以重新使用前面刻意延後的「多個輸出」介面：

```c
int find_min_max(const int values[], int length,
                 int *min_out, int *max_out);
```

先定義契約：

- `values` 必須代表至少 `length` 個可讀的 `int` 元素。
- `length <= 0` 時失敗。
- `min_out` 與 `max_out` 在第一版都不可為 `NULL`。
- 失敗時不修改任何輸出物件。
- 成功時兩個結果都寫入。
- 第一版允許 `min_out == max_out`。

最後一條需要小心。

如果兩個輸出可能是同一物件，先在區域變數完成分析：

```c
int local_min = values[0];
int local_max = values[0];
```

走訪完後，再依介面定義的順序寫出：

```c
*min_out = local_min;
*max_out = local_max;
```

若兩個指標相同，第二次寫入會成為最後留下的值。這表示「允許 aliasing」還不夠，介面還要說明 aliasing 時哪個結果最後可觀察到。

如果你覺得這個契約沒有實際價值，也可以改成明確禁止 `min_out == max_out`。好的介面不是允許越多情況越好，而是規則清楚且可驗證。

---

## 12. 修改需求：允許省略其中一個輸出

新規則：

> `min_out` 或 `max_out` 可以其中一個是 `NULL`，表示呼叫者不需要那個結果；但兩者不能同時為 `NULL`。

現在你必須先更新契約，再改實作。

成功寫出結果時也要分別檢查：

```c
if (min_out != NULL) {
    *min_out = local_min;
}

if (max_out != NULL) {
    *max_out = local_max;
}
```

不要因為「某個輸出是 optional」就先解參照再檢查。

測試至少包含：兩個都要、只要最小值、只要最大值、兩個都省略、空資料、以及你對 aliasing 做出的契約決策。

## 13. 選做：讓 AI 挑戰你的指標圖

這一節完全可以跳過。

先不用任何工具，自己畫圖並解釋：

> `int value = 10; int *p = &value;` 中，物件、值、位址、指標與 `*p` 分別是什麼？一個指標要能安全解參照，除了「不是 `NULL`」以外還需要哪些條件？

如果你想多做一次檢查，可以把圖與解釋交給 AI，請它提出一個 `NULL` 以外仍不能解參照的反例。你不需要固定 Prompt，也不需要保存或繳交對話。

如果 AI 的說法和物件生命週期、陣列邊界或可重現程式衝突，就回到這些證據重新判斷。

---

## 14. 離開這個 Unit 前，確認你真的能追蹤「指到哪裡」

直接回答：

- `score`、`&score`、`p`、`*p` 各代表什麼？
- 為什麼 `*p = 90` 改的是目標物件，而不是把指標本身變成 90？
- `scanf` 為什麼需要 `&score`？
- `NULL` 能不能被比較？能不能被解參照？
- 為什麼一個不是 `NULL` 的指標仍可能因生命週期結束而失效？
- 兩個指標指向同一物件時，透過其中一個修改，另一個為什麼看得到？
- 陣列表達式在大多數情境下如何和第一個元素位址連起來？
- 為什麼 `values + length` 可以作為 one-past 結束位置，卻不能被解參照？

如果某一題只能背一句話，就把物件畫成方格，把指標畫成箭頭，再走一次讀取或寫入。

---

## 15. 本章收尾

前面幾個 Unit 一直在使用「位置」，但刻意沒有一次把模型塞滿：`scanf` 需要寫入位置、陣列參數讓函數看到元素、字串函式沿著字元位置走訪、遞迴又提醒我們物件有生命週期。

F-U06 把這些線索收斂成指標模型：**指標保存位置；解參照透過位置存取物件；安全性則同時受初始化、nullability、生命週期、陣列邊界與 aliasing 影響。**

下一個 Unit 會把注意力從「如何找到一個物件」轉成「一個物件能不能同時包含不同種類的欄位」。例如一個學生同時有學號、姓名與成績；這就是結構（structure）要解決的資料組織問題。
