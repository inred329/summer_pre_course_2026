# 正式單元 F-U04：文字資料如何被表示與處理？

版本：1.1.0  
狀態：正式學生教材  
最後更新：2026-08-09  
對應英文版本：[Formal Unit F-U04: How Is Text Represented and Processed as Data?](unit-04-strings.en.md)

F-U03 讓我們把許多同型資料放進陣列，並用索引逐格走訪。

現在把元素型別從 `int` 換成 `char`：

```c
char letters[4] = {'c', 'a', 't', '?'};
```

它已經是一個字元陣列，但如果我們想讓它代表文字 `cat`，新的問題出現了：

> 陣列有容量，卻沒有自動告訴函式「文字到哪一格結束」。C 程式到底怎麼知道一串文字在哪裡停止？

C 字串的核心規則，就是在陣列內容中加入一個明確的終止記號。

---

## 1. `"cat"` 實際上還多一格

寫：

```c
char word[] = "cat";
```

可以先把它畫成：

```text
索引:   0    1    2    3
內容:  'c'  'a'  't' '\0'
```

前三格是可見文字，最後一格是 **空字元（null character）** `\0`。

因此 C 字串不是一個獨立的內建基本型別。最常見的模型是：

> **一串 `char` 元素，並且在文字結尾放一個 `\0`。**

這也立刻帶出 F-U03 的兩個舊問題：位置是否合法？內容是否有效？只是現在又多了一個新問題：終止符有沒有出現在正確位置？

---

## 2. 字元陣列不一定是 C 字串

下面這個陣列：

```c
char letters[3] = {'c', 'a', 't'};
```

有三個合法、已初始化的字元元素，但沒有 `\0`。

所以它是一個字元陣列，卻不是一個可以交給一般 C 字串函式安全處理的 C 字串。

相對地：

```c
char word[4] = {'c', 'a', 't', '\0'};
```

才具有完整的字串終止規則。

像 `printf("%s", word)`、`strlen(word)`、`strcmp(...)` 這類介面會依字串規則繼續讀取，直到找到 `\0`。如果終止符不存在於可讀範圍內，它們不會因為「陣列原本只有三格」就自動知道要停。

---

## 3. 容量、字串長度、需要的空間是三個不同數字

看：

```c
char name[20] = "Amy";
```

這裡：

- 陣列容量是 20 個 `char`。
- 目前文字長度是 3。
- 保存 `"Amy"` 至少需要 4 格，因為還有 `\0`。

可以畫成：

```text
索引:   0    1    2    3    4 ... 19
內容:  'A'  'm'  'y' '\0'  ...
```

之後看到任何字串緩衝區，都先問：

> 最多允許多少可見字元？還有沒有替 `\0` 留一格？

例如容量 20 的陣列，最多只能保存 19 個可見字元再加一個終止符。

---

## 4. `fgets` 把「容量」直接帶進讀取規則

讀一整行時，可以先用：

```c
#include <stdio.h>

int main(void) {
    char name[20];

    if (fgets(name, sizeof name, stdin) == NULL) {
        fprintf(stderr, "Input failed.\n");
        return 1;
    }

    printf("Hello, %s", name);
    return 0;
}
```

`sizeof name` 在這裡是整個陣列的容量，也就是 20。

對這次呼叫而言，`fgets` 最多把 `capacity - 1` 個字元放進陣列，並替成功讀入的內容保留終止 `\0`。

但「成功」不等於「整個邏輯輸入行一定完整放進來」。

假設容量只有 8，而使用者輸入：

```text
Alexander\n
```

緩衝區一次裝不下整行。`fgets` 可以成功取得前面一段並補上 `\0`，但後面的字元仍留在輸入資料流中，等待下一次讀取。

所以接下來真正需要判斷的是：

> 這次讀到的是完整一行，還是只有前半段？

---

## 5. 換行字元可以幫我們辨認「完整讀到一行」

如果使用者按 Enter，而且這個換行也成功被 `fgets` 放進陣列，我們通常會看到：

```text
'A' 'm' 'y' '\n' '\0'
```

很多程式希望最後保存的是 `"Amy"`，所以可以找到 `\n` 再改成 `\0`。

使用 `<string.h>` 的 `strcspn`：

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char text[20];

    if (fgets(text, sizeof text, stdin) == NULL) {
        fprintf(stderr, "Input failed.\n");
        return 1;
    }

    size_t newline = strcspn(text, "\n");

    if (text[newline] == '\n') {
        text[newline] = '\0';
        printf("Complete line: %s\n", text);
    } else {
        printf("No newline was stored.\n");
    }

    return 0;
}
```

注意最後一句訊息只說「這次緩衝區裡沒有換行」，還沒有自動證明是哪一種原因。

可能是：

- 這一行太長，被容量截斷。
- 輸入來源在沒有換行的最後一行就遇到 EOF。

如果你的程式規格要求「一定要取得一個完整、以換行結束的互動輸入行」，就必須把這些情況明確定義並處理。

---

## 6. 如果一行太長，下一次讀取前要處理殘留資料

以下是一個適合互動式文字輸入的簡化函數。它把「完整讀到換行」視為成功；如果目前緩衝區沒有換行，就把這一行剩下的字元讀掉，避免下一次 `fgets` 接著讀到同一行的後半段。

```c
#include <stdio.h>
#include <string.h>

int read_line(char text[], size_t capacity) {
    if (capacity == 0) {
        return 0;
    }

    if (fgets(text, capacity, stdin) == NULL) {
        return 0;
    }

    size_t newline = strcspn(text, "\n");
    if (text[newline] == '\n') {
        text[newline] = '\0';
        return 1;
    }

    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF) {
        /* 丟棄目前這一行尚未讀完的字元 */
    }

    return 0;
}
```

這裡先把 `text[]` 理解成「呼叫者提供的字元陣列」，把 `capacity` 理解成「最多可以安全使用多少格」。陣列參數與指標的底層關係仍留到 F-U06。

這個函數的規格也刻意很簡單：

- 回傳 `1`：這次確實讀到換行，換行已移除。
- 回傳 `0`：容量不合法、讀取失敗，或這次沒有取得完整的換行結束行。

測試時至少要分開看：空行、短文字、剛好能完整容納的行、過長行，以及讀取前就遇到 EOF。

---

## 7. 手動走訪字串，其實就是「走訪陣列直到特殊元素」

還記得 F-U03 的陣列迴圈嗎？字串走訪非常像，只是終止條件不再是固定長度，而是遇到 `\0`：

```c
int length = 0;
while (name[length] != '\0') {
    length++;
}
```

對 `"Amy"`：

| 索引 | 字元 | 是否結束？ |
|---:|---|---|
| 0 | `A` | 否 |
| 1 | `m` | 否 |
| 2 | `y` | 否 |
| 3 | `\0` | 是 |

所以字串長度 3，不包含終止符本身。

這也解釋了為什麼「缺少 `\0`」這麼危險：走訪規則失去了合法的停止點。

---

## 8. 常用字串函式都依賴同一個前提：輸入真的是字串

`<string.h>` 提供很多函式，例如：

```c
strlen(text)
strcmp(a, b)
strcpy(destination, source)
```

它們的目的不同，但有一個共同的閱讀前提：需要當作字串讀取的輸入必須在可讀範圍內具有 `\0`。

### `strlen`

回報終止符以前的字元數，不把 `\0` 算進長度。

### `strcmp`

比較兩個字串內容。相等時回傳 0，所以應寫：

```c
if (strcmp(a, b) == 0) {
    printf("equal\n");
}
```

不要把它背成「回傳 true 表示相等」。

### `strcpy`

會把來源字串連同終止符複製到目的陣列，但它不會替你證明目的容量足夠。因此在不知道容量是否足夠時，不能只是看到函式名稱像「copy」就放心使用。

這一章的重點不是背所有字串函式，而是先建立一個固定檢查：**終止符在哪裡？目的容量夠嗎？**

---

## 9. 三個很容易混淆的案例

### 案例 A：`char word[3] = "cat";`

這一行在 C 中可以建立三個元素：

```text
'c' 'a' 't'
```

因為容量剛好只夠三個可見字元，所以沒有空間保存 `\0`。

因此它可以是一個合法初始化的字元陣列，**但不是一個具有終止符的 C 字串**。這和「編譯器一定會拒絕它」是不同概念。

若你接著把它交給要求 C 字串的函式，函式會繼續尋找 `\0`，可能讀出陣列範圍，造成未定義行為。

### 案例 B：用 `==` 想比較兩段文字內容

```c
if (a == b) {
    /* ... */
}
```

這不是逐字元比較兩個 C 字串內容。這個運算牽涉的是陣列表達式轉換後的指標值；完整模型會在 F-U06 建立。

目前只要抓住一件事：**比較字串內容要用內容比較規則，例如 `strcmp(a, b) == 0`。**

### 案例 C：`fgets` 成功就假設讀完整行

`fgets` 成功代表它取得了一些輸入並建立了終止字串，不代表使用者的整個邏輯輸入行一定已全部進入這個緩衝區。

如果你的規格要求完整行，就必須檢查換行、容量與殘留輸入，而不是只看「函式沒有失敗」。

---

## 10. 做三個小實驗，把容量與終止條件畫出來

### 實驗 A：手動算長度

使用：

```c
char text[] = "hello";
```

先畫出六格：五個可見字元加 `\0`，再寫迴圈算出長度。

### 實驗 B：計算母音

逐格走訪到 `\0`，每次只處理目前 `text[i]`。先用全小寫輸入，避免一次又加入大小寫轉換問題。

### 實驗 C：刻意使用很小的輸入陣列

例如：

```c
char text[6];
```

分別輸入短字、剛好能連同換行完整容納的內容，以及超過容量的內容。每次都畫出陣列實際保存了哪些字元，觀察換行是否真的進入陣列。

## 11. 自主練習：文字分析器

讀入一個你定義為「必須完整取得」的輸入行，若發生截斷或讀取失敗就明確回報，不要默默分析前半段。

成功取得一行後，輸出：

- 字串長度
- 空白數量
- 數字字元數量
- 第一個字元與最後一個字元（僅限非空字串）

測試至少包含：

| 情況 | 要確認什麼？ |
|---|---|
| 空行 | 長度 0，不可讀取不存在的第一／最後字元 |
| 一般短文字 | 基本走訪 |
| 包含空白 | 空白不能讓讀取提早停止 |
| 剛好可完整容納 | 邊界仍有終止符與換行處理 |
| 過長輸入 | 不可默默只分析前半段 |

這個練習其實一直重複同一個模型：

```text
容量 → 是否完整讀入 → 終止符 → 合法走訪 → 元素分類
```

---

## 12. 修改需求：只統計英文字母

現在把文字分析器改成：

> 忽略空白、數字與標點，只統計英文字母數量。

不要先改程式。先增加幾個測試：

```text
abc
A1b2!
hello, world!
12345
```

再決定英文字母的分類方式。

如果使用 `<ctype.h>` 的 `isalpha`，記得這類分類函式的參數要符合它的有效輸入契約；在處理任意 `char` 值時，常見安全寫法是先轉成 `unsigned char` 再傳入。這個細節會在後續更深入的介面與表示討論中再次出現。

修改完成後，把原本的空行、長行與邊界案例全部再跑一次，確認「分類規則改變」沒有破壞「完整讀入與安全走訪」。

## 15. 本章收尾

F-U03 建立「陣列有固定位置範圍」；F-U04 再加入一個文字特有的協定：**即使陣列還有剩餘容量，字串也會在第一個 `\0` 結束。**

因此安全處理文字時，要同時追蹤兩種邊界：陣列容量決定哪裡可以存取，終止符決定哪裡屬於目前這段字串內容。輸入時還要再確認整個邏輯輸入是否真的完整進入緩衝區。

下一個 Unit 會把注意力從「資料放在哪一格」轉向「函數呼叫時，程式執行到哪裡」。我們已經多次呼叫 `sum_array`、`max_array`、`strlen`、`strcmp`；接下來要追問的是：每次進入函數時，參數與區域變數如何形成自己的執行狀態？如果函數又呼叫另一個函數，甚至呼叫自己，這些狀態又如何彼此分開？
