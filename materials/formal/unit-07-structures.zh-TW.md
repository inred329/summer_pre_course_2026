# 正式單元 F-U07：資料結構如何由多個不同欄位組成？

版本：1.1.0  
狀態：正式學生教材  
最後更新：2026-08-09  
對應英文版本：[Formal Unit F-U07: How Can One Data Object Contain Different Fields?](unit-07-structures.en.md)

F-U06 解決的是「怎麼找到一個物件，甚至讓函數透過指標修改它」。

但現在換一個資料組織問題。假設我們要描述一位學生：

```c
char name[20];
int id;
double average;
```

三個變數都沒有錯，問題是它們其實屬於**同一個學生**。當學生變成十位、五十位時，如果姓名、學號與平均分散在不同地方，我們很容易失去「哪些欄位屬於同一筆資料」的關係。

所以這一章的問題是：

> 如果一個實體同時具有不同型別的欄位，C 要怎麼把它們組成一個有意義的資料物件？

這就是 `struct`。

---

## 1. 先把一位學生組成一個型別

```c
struct Student {
    char name[20];
    int id;
    double average;
};
```

可以想成：

```text
Student
├── name      char[20]
├── id        int
└── average   double
```

這段程式定義的是一種**型別**，還沒有建立任何實際學生。

真正建立物件要再寫：

```c
struct Student s;
```

現在 `s` 才是一個 `struct Student` 物件。

這個區分很重要：

- `struct Student`：描述「這種資料長什麼樣」。
- `s`：執行時真正存在的一筆學生資料。

---

## 2. 結構物件建立了，不代表每個欄位已有有效資料

如果只寫：

```c
struct Student s;
```

不要立刻：

```c
printf("%d\n", s.id);
printf("%s\n", s.name);
```

一般自動區域物件的這些欄位尚未因為「放進 struct」就自動得到可依賴的值。

其中：

- `id`、`average` 尚未被初始化。
- `name` 雖然有 20 個字元位置，但不保證其中存在可以作為 C 字串終點的 `\0`。

所以 F-U03、F-U04 的規則沒有消失：**合法欄位位置不等於欄位內容已有效。**

最直接的做法是建立時就完整初始化：

```c
struct Student s = {"Amy", 1001, 87.5};
```

現在三個欄位都有定義清楚的內容。

---

## 3. `.` 表示「從這個結構物件裡取某個欄位」

對：

```c
struct Student s = {"Amy", 1001, 87.5};
```

可以寫：

```c
printf("%s\n", s.name);
printf("%d\n", s.id);
printf("%.1f\n", s.average);
```

也可以修改單一欄位：

```c
s.average = 90.0;
```

`.` 左邊是結構物件，右邊是它的成員名稱。

如果某個物件會先建立、之後才逐步填值，可以先零初始化：

```c
struct Student empty = {0};
```

這會讓數值欄位從 0 開始，`name[0]` 也會是 `\0`，因此 `name` 一開始就是空字串。

---

## 4. `typedef` 只是在替型別取一個比較短的名字

一直寫 `struct Student` 有時很冗長，所以常見寫法是：

```c
typedef struct {
    char name[20];
    int id;
    double average;
} Student;
```

之後：

```c
Student s = {"Amy", 1001, 87.5};
```

`typedef` 建立的是型別別名，不會偷偷建立任何學生物件。

你可以把它讀成：

> 之後用 `Student` 這個名稱表示這種結構型別。

---

## 5. 結構遇到指標後，`->` 就有了自然意義

F-U06 已經知道，如果：

```c
Student s = {"Amy", 1001, 87.5};
Student *p = &s;
```

那麼 `p` 指向 `s`。

要透過這個指標修改 `average`，可以寫：

```c
(*p).average = 90.0;
```

因為 `*p` 先得到 `Student` 物件，再用 `.` 取欄位。

C 提供更常見的寫法：

```c
p->average = 90.0;
```

所以：

```text
p->member
```

就是：

```text
(*p).member
```

的簡潔寫法。

這也終於解釋了為什麼 F-U06 沒有提前介紹 `->`：先有結構成員，這個符號才有真正可理解的用途。

---

## 6. 要不要用值傳遞或指標傳遞，看函數要做什麼

如果只是讀取一筆小型結構並輸出：

```c
void print_student(Student s) {
    printf("%s %d %.1f\n", s.name, s.id, s.average);
}
```

這是值傳遞；函數收到一份結構值。

如果要修改呼叫者的原物件，就需要位置：

```c
#include <math.h>
#include <stddef.h>

int update_average(Student *s, double value) {
    if (s == NULL || !isfinite(value) ||
        value < 0.0 || value > 100.0) {
        return 0;
    }

    s->average = value;
    return 1;
}
```

這時 F-U06 的問題全部重新出現：

- `s` 可不可以是 `NULL`？
- `s` 指向的物件還在生命週期內嗎？
- 函數是否有權修改它？

如果函數只需要透過指標讀取，可以表達成：

```c
const Student *s
```

表示函數不應透過這個參數修改該 `Student` 值。

---

## 7. 結構裡的字串欄位仍然受到容量限制

`name` 是：

```c
char name[20];
```

所以它仍然遵守 F-U04 的字串規則。

不能因為它現在躲在 `Student` 裡，就忘記容量。

一個明確拒絕截斷的設定函數可以寫成：

```c
#include <stddef.h>
#include <stdio.h>

int set_name(Student *s, const char *name) {
    if (s == NULL || name == NULL) {
        return 0;
    }

    int written = snprintf(s->name, sizeof s->name, "%s", name);

    if (written < 0 || (size_t)written >= sizeof s->name) {
        s->name[0] = '\0';
        return 0;
    }

    return 1;
}
```

這裡的政策是：

> 名字完整放得下才成功；太長就回傳失敗，而且不留下看起來像完整姓名的截斷結果。

你也可以設計其他政策，例如允許截斷，但一定要明確說明並測試。真正危險的是沒有政策，卻假設字串一定放得下。

---

## 8. 結構指定會複製整個結構值

```c
Student a = {"Amy", 1001, 87.5};
Student b = a;
```

這會把 `a` 的結構值指定給 `b`。

因為 `name` 是結構內的陣列成員，陣列中的元素也會成為複製後 `b` 的一部分。

所以之後：

```c
b.average = 60.0;
b.name[0] = 'E';
```

不會因此修改 `a.average` 或 `a.name[0]`。

但如果結構裡的欄位本身是指標，情況不同：結構指定複製的是**指標值**，不是自動複製指標所指向的另一個物件。

這會在 F-U08 的動態記憶體與所有權問題中變得非常重要。

---

## 9. 結構沒有內建的「整筆 ==」比較

不能寫：

```c
if (a == b) {
    /* ... */
}
```

C 不提供一般結構值的 `==` 比較。

而且從需求角度看，這反而提醒我們先問一個更重要的問題：

> 什麼叫做「兩位學生相同」？

可能是：

- 學號相同就視為同一人。
- 學號、姓名、平均都要相同。
- 只比較某些欄位。

如果要比較姓名內容，仍要用字串內容比較，例如 `strcmp`。

所以比較規則應該來自需求，而不是期待 struct 自動替你決定「相等」的意思。

---

## 10. 結構陣列把 F-U03 和這一章接在一起

三位學生可以寫成：

```c
Student students[3] = {
    {"Amy", 1001, 87.5},
    {"Ben", 1002, 91.0},
    {"Cara", 1003, 78.0}
};
```

走訪：

```c
for (int i = 0; i < 3; i++) {
    printf("%d %s %.1f\n",
           students[i].id,
           students[i].name,
           students[i].average);
}
```

讀 `students[i].average` 時，可以分三層想：

```text
i
→ students[i] 找到第 i 個 Student
→ .average 找到這位學生的 average 欄位
```

F-U03 的索引邊界完全沒變，只是每個元素現在不再是一個 `int`，而是一整筆 `Student`。

---

## 11. 自主練習：做一個小型學生資料分析器

建立最多 10 位學生的結構陣列。

每筆資料至少包含：

```text
id
name
average
```

需求：

1. 找出平均最高者。
2. 計算全班平均。
3. 依學號查詢學生。

在寫程式以前，先決定：

- 學號可以重複嗎？
- 姓名超過 19 個可見字元時怎麼處理？
- `average` 是否限定 0～100，是否拒絕 NaN／Infinity？
- 如果最高分同分，要回傳第一位、全部，還是依學號決定？
- 如果目前沒有學生，「最高者」與「全班平均」要怎麼回報？

這些不是額外麻煩，而是把「Student 到底代表什麼有效資料」說清楚。

建議測試至少包含：空集合、單一學生、同分、找不到學號、過長姓名、無效平均與正常多筆資料。

---

## 12. 修改需求：加入 `grade`

現在新增欄位：

```c
char grade;
```

它由 `average` 推導，例如：

```text
90–100 → A
80–89  → B
70–79  → C
其他   → D
```

不要只在 struct 裡多打一行就結束。

重新找出所有被這個需求影響的地方：

- 初始化資料。
- 平均修改後，grade 是否也要同步更新？
- 輸出格式。
- 比較／查詢規則。
- 測試資料，尤其 79/80、89/90 等邊界。

這個修改要讓你看見：**把資料組成一個物件之後，欄位之間可能具有一致性關係。**

---

## 13. 選做：讓 AI 挑戰你的資料模型

這一節完全可以跳過。

先不用任何工具，自己回答：

> 為什麼 `Student` 比三組分散變數更能表達資料關係？如果 `average` 改了，哪些其他欄位或規則可能需要一起維持一致？

如果你想多做一次檢查，可以把自己的 `Student` 設計交給 AI，請它找出一個「單一欄位看起來合法，但整筆資料彼此矛盾」的案例。你不需要固定 Prompt，也不需要保存或繳交對話。

如果 AI 的建議和字串容量、指標契約、欄位範圍或可重現測試衝突，就回到這些證據重新判斷。

---

## 14. 離開這個 Unit 前，確認你不是只在背 `struct` 語法

直接回答：

- `Student` 型別和某一個 `Student s` 物件有什麼不同？
- 為什麼 `Student s;` 不代表所有欄位都已有安全可讀的資料？
- `s.average` 和 `p->average` 分別在什麼情況使用？
- `p->member` 為什麼等價於 `(*p).member`？
- 結構指定會如何處理陣列欄位？如果欄位是指標，又複製了什麼？
- 為什麼姓名放進 struct 後仍然要管理 `\0` 與容量？
- 為什麼「兩個 Student 是否相等」應該先由需求定義？
- `students[i].average` 可以拆成哪兩次定位？

如果回答只剩符號規則，回到一位學生的圖，把「整個物件」和「物件中的欄位」重新畫一次。

---

## 15. 本章收尾

F-U06 教我們如何透過位置找到一個物件；F-U07 則讓一個物件本身可以由多個不同型別的欄位組成。

`struct` 真正帶來的價值不是少寫幾個變數名稱，而是把**屬於同一實體的資料與規則放回同一個模型裡**。初始化、字串容量、欄位驗證、指標有效性與比較規則仍然要被維持，只是現在它們共同守護的是一整筆資料。

下一個 Unit 會再改變一件事：目前陣列與結構物件的大小大多在寫程式時就決定了。如果資料筆數直到執行時才知道，而且需要的空間可能增減，我們要怎麼在執行期間取得與釋放儲存空間？這就進入動態記憶體與所有權。
