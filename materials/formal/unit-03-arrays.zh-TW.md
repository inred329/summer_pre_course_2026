# 正式單元 F-U03：資料如何形成有順序的集合？

版本：1.1.0  
狀態：正式學生教材  
最後更新：2026-08-09  
對應英文版本：[Formal Unit F-U03: How Does Data Form an Ordered Collection?](unit-03-arrays.en.md)

F-U02 最後處理的是「不知道會輸入幾筆資料」：我們可以一筆一筆讀、判斷、累加，處理完就繼續下一筆。

但如果需求改成：

> 先把五次成績全部保留下來，之後還要重看其中某一筆、找最大值、修改某一筆，甚至用不同方式重新分析呢？

這時只有 `sum` 和 `count` 已經不夠了。我們需要同時保存一整組資料，而且還要知道每一筆放在哪裡。

這就是陣列要解決的問題。

---

## 1. 五個變數還能寫，五十個就開始失控

你當然可以寫：

```c
int score1 = 80;
int score2 = 90;
int score3 = 75;
int score4 = 88;
int score5 = 92;
```

但如果要算平均，你還得一個一個寫；如果有五十筆，命名、處理、修改與測試都會變得重複而且容易漏掉。

陣列讓我們把「同一類、同一型別」的資料放成一個有順序的集合：

```c
int scores[5] = {80, 90, 75, 88, 92};
```

可以先把它畫成：

```text
索引:   0   1   2   3   4
值:    80  90  75  88  92
```

這裡有三個名詞要一起看：

- `scores` 是陣列。
- 每一格資料是一個元素（element）。
- 元素的位置用索引（index）表示。

長度是 5，但合法索引不是 1～5，而是 **0～4**。

這個「從 0 開始」的規則之後會一直影響迴圈與邊界。

---

## 2. 索引回答的是「哪一格」，不是「這一格的值」

例如：

```c
printf("%d\n", scores[2]);
```

`scores[2]` 指的是索引 2 的元素，也就是第三格，值是 `75`。

如果寫：

```c
scores[2] = 78;
```

陣列就變成：

```text
索引:   0   1   2   3   4
值:    80  90  78  88  92
```

所以閱讀 `scores[i]` 時，可以固定分兩步：

1. 先算出 `i` 是多少。
2. 再去陣列中找到那一格。

這能避免一個很常見的混淆：索引是位置，元素才是資料。

---

## 3. 陣列和迴圈會自然放在一起

F-U02 已經學過重複流程。現在我們第一次讓迴圈的控制變數同時扮演「陣列位置」的角色：

```c
int sum = 0;

for (int i = 0; i < 5; i++) {
    sum += scores[i];
}
```

逐輪追蹤：

| `i` | `scores[i]` | 更新後 `sum` |
|---:|---:|---:|
| 0 | 80 | 80 |
| 1 | 90 | 170 |
| 2 | 75 | 245 |
| 3 | 88 | 333 |
| 4 | 92 | 425 |

這個迴圈有一個很漂亮的對應：

```text
合法索引：0, 1, 2, 3, 4
迴圈 i ：0, 1, 2, 3, 4
```

所以條件是：

```c
i < 5
```

而不是：

```c
i <= 5
```

如果 `i == 5` 還進入迴圈，`scores[5]` 已經不是這個陣列的元素。

---

## 4. 越界不是「拿到奇怪資料」而已

看：

```c
int values[5] = {10, 20, 30, 40, 50};
printf("%d\n", values[5]);
```

合法索引只有 0～4，所以 `values[5]` 越界。

在 C 中，這不是「保證印出某個垃圾值」的規則，而是**未定義行為（undefined behavior）**。某一次執行看起來沒事，不能證明這個存取安全。

因此看到陣列迴圈時，一個非常實用的檢查方式是把兩件事放在一起看：

> 迴圈最後一次可能出現的 `i` 是多少？這個值仍然是合法索引嗎？

例如：

```c
for (int i = 0; i <= 5; i++) {
    printf("%d\n", values[i]);
}
```

不必執行就能找到問題：最後會出現 `i == 5`，而長度為 5 的陣列最後索引是 4。

---

## 5. 「有五格」不代表五格都有可讀的值

再看另一段：

```c
int values[5];
```

它確實建立了五個 `int` 元素，但這些區域自動變數元素沒有因為「是陣列」就自動得到可靠的 0。

如果立刻寫：

```c
printf("%d\n", values[0]);
```

你是在讀尚未初始化的元素；這不是可以依賴的程式行為。

所以「索引合法」只是第一個條件。

在讀取某一格以前，還要問：

> 這一格是否已經由初始化或成功輸入得到有效值？

如果資料是從使用者輸入進來，更要把 F-U02 的原則帶回來：先確認 `scanf` 成功，而且資料符合範圍，再把它放進陣列。

---

## 6. 把陣列交給函數時，長度也要一起交代

假設我們希望把加總責任從 `main` 分出去：

```c
int sum_array(const int values[], int length) {
    int sum = 0;

    for (int i = 0; i < length; i++) {
        sum += values[i];
    }

    return sum;
}
```

呼叫：

```c
int total = sum_array(scores, 5);
```

為什麼要有 `length`？

因為函數不能只看到參數寫成 `values[]` 就自動知道呼叫者這次打算提供幾個可用元素。這個介面必須把「可以走訪多少格」一起說清楚。

現在先把：

```c
const int values[]
```

理解成「這個函數會讀取一組 `int` 元素，而且不修改它們」。陣列參數在 C 裡和指標的實際關係會在 F-U06 正式建立；這裡先把注意力放在**元素、索引、長度與走訪契約**。

這個最小範例還有一個刻意說清楚的前提：所有元素總和必須能由 `int` 表示。F-U01 已經知道有號整數溢位是未定義行為，所以資料範圍若可能很大，就必須改用足夠的型別或在加法前做邊界檢查。

---

## 7. 找最大值以前，先處理「沒有元素」這件事

常見寫法會用第一個元素當初始最大值：

```c
int max_array(const int values[], int length) {
    int max = values[0];

    for (int i = 1; i < length; i++) {
        if (values[i] > max) {
            max = values[i];
        }
    }

    return max;
}
```

這個函數有一個重要前提：

> `length` 必須大於 0。

原因很直接。如果 `length == 0`，就根本沒有第一個元素，`values[0]` 也就不合法。

所以呼叫者要在呼叫前處理空集合：

```c
if (length > 0) {
    int maximum = max_array(values, length);
    printf("Max: %d\n", maximum);
} else {
    printf("No data\n");
}
```

這個版本刻意只使用目前已建立的函數回傳值，不先引入輸出指標與 `NULL`。等到 F-U06 建立完整指標模型後，再回頭看「函數如何同時回報成功／失敗與輸出資料」會更自然。

## 8. 用同一個陣列做三種走訪

先用：

```c
int values[5] = {3, -2, 7, -1, 4};
```

### 任務 A：全部加總

```c
int sum = 0;
for (int i = 0; i < 5; i++) {
    sum += values[i];
}
```

### 任務 B：把負值改成 0

```c
for (int i = 0; i < 5; i++) {
    if (values[i] < 0) {
        values[i] = 0;
    }
}
```

### 任務 C：計算大於等於 4 的元素數量

```c
int count = 0;
for (int i = 0; i < 5; i++) {
    if (values[i] >= 4) {
        count++;
    }
}
```

三段程式的索引路徑完全一樣，差別在「每一格要做什麼」。

這正是陣列的力量：資料規模變大時，我們不需要替每一筆重新發明一個變數名稱，只需要把一個可靠的元素操作放進走訪流程。

## 9. 自主練習：做一個十人成績分析器

讀入固定 10 個成績，最後輸出：

- 平均
- 最大值
- 最小值
- 及格人數

先決定有效成績範圍，例如 0～100。

輸入時不要先把資料塞進陣列再想辦法處理。每一筆都應該經過：

```text
讀取成功？ → 範圍有效？ → 才寫入下一個陣列元素
```

接著至少建立這幾種資料：

| 測試資料 | 想觀察什麼？ |
|---|---|
| 全部相同 | 最大、最小、平均是否一致 |
| 遞增 | 邊走訪邊更新是否正確 |
| 遞減 | 不可依賴輸入順序 |
| 包含 59 與 60 | 及格邊界 |
| 包含 0 與 100 | 合法範圍邊界 |
| 無效文字 | 不得寫入陣列 |
| 超出範圍 | 不得成為分析資料 |

如果你用 `int` 累加十個 0～100 的成績，總和最多 1000，因此這個練習的加總範圍很容易先證明安全。

這也是一個好習慣：不要等到「可能溢位」才想型別，先由需求範圍算出最壞情況。

---

## 10. 修改需求：去掉一個最低分再算平均

現在把需求改成：

> 十個有效成績中，移除一個最低分，再計算剩下九筆的平均。

「移除」不一定代表真的把陣列元素搬來搬去。

如果你已經知道：

- 所有分數總和 `sum`
- 最低分 `min`
- 元素個數 `count`

那麼新的平均可以由：

```text
(sum - min) / (count - 1)
```

的概念得到。

這個修改值得注意的不是公式本身，而是你可以先問：

> 需求真正改變的是資料內容，還是我們對這組資料的分析方式？

在固定十筆有效成績的版本中，`count - 1` 一定是 9，不會除以零。

如果未來把函數寫成可接受任意長度，就必須重新定義：空陣列或只有一個元素時，「移除最低分後平均」到底是否有意義。

## 12. 離開這個 Unit 前，確認你能把「位置」和「資料」分開想

回到本章程式，直接回答：

- 長度為 `n` 的陣列，最後一個合法索引為什麼是 `n - 1`？
- `scores[2]` 中的 `2` 和元素值有什麼不同？
- 為什麼 `i < length` 通常比把最後索引硬寫在迴圈裡更容易維護？
- 為什麼合法索引仍不代表該元素已經初始化？
- 越界為什麼不能用「這次剛好印出正常值」來證明安全？
- 為什麼陣列交給函數時通常還要提供長度？
- `max_array` 為什麼要求 `length > 0`？
- 當需求從「分析十筆成績」變成「去掉最低分再分析」時，哪些資料真的需要改、哪些只需要重新計算？

如果某一題只能背一句規則，就畫出索引和值，再用一個很小的陣列自己走一次。

## 13. 本章收尾

F-U02 解決的是「資料來一筆，就可靠地決定怎麼處理這一筆」；F-U03 則讓我們第一次能把多筆同型資料同時留下來，再依位置反覆查看與分析。

陣列把多個元素組成有順序的集合。可靠操作的核心不是背 `[]` 語法，而是一直維持三件事：**目前有多少有效元素、合法索引到哪裡、每一格是否真的已經有有效資料。**

下一個 Unit 會出現一種非常常見、看起來又很熟悉的陣列：文字。

在 C 裡，字串不是一個獨立的神奇基本型別；它會用字元陣列來保存，而且還多了一個重要規則——程式要知道文字在哪裡結束。這會讓我們把今天的「長度與邊界」再往前推一步。
