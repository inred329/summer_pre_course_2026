## 核心問題

> 當多個同類資料需要一起保存與處理時，程式如何組織、定位與走訪它們？

完成本章後，你應能：

1. 說明陣列、元素、索引與長度。
2. 追蹤一維陣列走訪。
3. 區分合法索引與越界。
4. 將陣列與長度傳給函數。
5. 使用邊界與空集合思考測試。

---

## 1. 為什麼不只用很多變數？

```c
int score1, score2, score3, score4, score5;
```

若資料筆數增加，逐一命名與處理會變得重複且容易漏掉。陣列讓多個同型別元素以連續索引組織。

---

## 2. 陣列模型

```c
int scores[5] = {80, 90, 75, 88, 92};
```

```text
索引:   0   1   2   3   4
值:    80  90  75  88  92
```

長度是 5，合法索引是 0 到 4。最後索引是 `length - 1`。

---

## 3. 存取與更新

```c
printf("%d\n", scores[2]);
scores[2] = 78;
```

先求索引，再定位元素，最後讀取或寫入。索引不是元素值。

---

## 4. 走訪陣列

```c
int sum = 0;

for (int i = 0; i < 5; i++) {
    sum += scores[i];
}
```

追蹤：

| `i` | `scores[i]` | 更新後 `sum` |
|---:|---:|---:|
| 0 | 80 | 80 |
| 1 | 90 | 170 |
| 2 | 75 | 245 |
| 3 | 88 | 333 |
| 4 | 92 | 425 |

條件使用 `i < 5`，不是 `i <= 5`。

---

## 5. 將長度一起傳入函數

```c
int sum_array(const int values[], int length) {
    int sum = 0;
    for (int i = 0; i < length; i++) {
        sum += values[i];
    }
    return sum;
}
```

函數通常無法只從參數 `values[]` 自動知道元素數量，因此介面要包含長度。

這個最小範例假設所有元素的總和都能以 `int` 表示。若資料範圍可能更大，介面必須改用足夠的型別，或在每次加法前檢查是否會溢位；有號整數溢位屬未定義行為。

---

## 6. 安全找最大值

若函數會讀取 `values[0]`，就必須先拒絕空集合。可用回傳狀態與輸出參數：

```c
int max_array(const int values[], int length, int *result) {
    if (values == NULL || result == NULL || length <= 0) {
        return 0;
    }

    int max = values[0];

    for (int i = 1; i < length; i++) {
        if (values[i] > max) {
            max = values[i];
        }
    }

    *result = max;
    return 1;
}
```

介面規則：

- 成功時回傳 `1`，並透過 `result` 寫出最大值。
- 輸入無效時回傳 `0`，不得讀取或寫入無效指標。
- 測試一般陣列、單一元素、`length == 0` 與空輸出指標。

---

## 7. 錯誤案例

### 越界

```c
int values[5];
printf("%d\n", values[5]);
```

合法索引只到 4。越界屬未定義行為，不能因一次看似正常就視為安全。

### 未初始化元素

```c
int values[5];
printf("%d\n", values[0]);
```

區域陣列不會自動包含可靠的 0；讀取未初始化元素屬未定義行為。

### 空集合取第一個元素

若 `length == 0` 時仍執行 `values[0]`，屬未定義行為。必須在任何元素存取前拒絕呼叫。

- 及格人數

## 10. 需求修改

新增需求：移除最低分後計算平均。不要真的改變陣列也可以；先定義「移除」對總和與筆數的影響，再更新測試。若陣列可能為空或只有一個元素，必須先定義此需求是否有效，以及失敗時的行為。
