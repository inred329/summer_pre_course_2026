## 文件目的

本文件提供本課程正式文件使用的中英文術語基準，確保領域模型、知識依賴、能力、範圍、驗收、交付、風險、教材與評量採用一致名稱。

本文件的主要讀者為教師、助教、教材作者、翻譯者與維護者。新增或修改重要術語時，必須同步更新中英文版本與受影響文件。

## 使用規則

1. 正式文件首次使用重要術語時，應在適當情況下同時提供中英文名稱。
2. 同一概念不得在不同文件中任意改名。
3. 英文翻譯應符合專業慣例，不以逐字翻譯為優先。
4. 同一英文詞若在不同語境具有不同意義，必須以說明欄區分。
5. 新增術語前，先確認是否已有可使用的既有術語。
6. 程式碼識別字、函式名稱與 C 語言關鍵字原則上不翻譯。

## 核心課程術語

| 中文 | 英文 | 使用說明 |
|---|---|---|
| 程式設計 | Programming | 指使用程式語言建立可執行問題解法的活動與能力。 |
| 領域模型 | Domain Model | 描述領域中有哪些概念及其關係，不代表授課順序。 |
| 知識依賴圖 | Knowledge Dependency Graph | 描述理解某概念前通常需要哪些先備知識。 |
| 能力地圖 | Competency Map | 描述學生必須能做到什麼，以及目標成熟度。 |
| 範圍邊界 | Scope Boundary | 定義核心交付、基礎鋪墊、延後與課程外內容。 |
| 驗收模型 | Acceptance Model | 定義能力成立所需的任務、證據與通過判準。 |
| 交付地圖 | Delivery Map | 將能力、成熟度與證據安排到課程階段與單元。 |
| 風險登錄表 | Risk Register | 記錄風險、觸發條件、緩解、應變與責任角色。 |
| 追蹤矩陣 | Traceability Matrix | 串連需求、概念、能力、驗收、交付與風險。 |
| 成熟度 | Maturity | 能力可觀察程度，分為辨識、解釋、追蹤、實作、診斷與遷移。 |
| 學習證據 | Learning Evidence | 支持學生能力成立的可觀察產出或行為。 |
| 核心交付 | Core Delivery | 課程階段結束時必須達成並留下正式證據的能力。 |
| 基礎鋪墊 | Foundation Only | 建立名詞、目的與模型，但不宣稱能獨立實作。 |
| 延後深化 | Deepen Later | 已建立初步能力，更高成熟度留到後續。 |
| 延後實作 | Implement Later | 可以理解或追蹤，但完整實作與診斷刻意延後。 |
| 課程外 | Out of Scope | 不屬於目前課程核心交付。 |

## 程式執行與工具鏈

| 中文 | 英文 | 使用說明 |
|---|---|---|
| 原始碼 | Source Code | 人類撰寫、交由工具鏈處理的程式文字。 |
| 前置處理器 | Preprocessor | 處理 `#include`、巨集與條件編譯。 |
| 編譯器 | Compiler | 將高階語言轉為較低階表示並進行語法語意檢查。 |
| 組譯器 | Assembler | 將組合語言轉為目的碼。 |
| 目的檔 | Object File | 編譯與組譯階段產生、尚待連結的檔案。 |
| 連結器 | Linker | 組合目的檔與函式庫形成可執行檔。 |
| 可執行檔 | Executable | 可由作業系統載入的程式映像。 |
| 載入器 | Loader | 將可執行檔映射為執行中的程序。 |
| 程序 | Process | 執行中的程式及其資源與狀態。 |
| 標準函式庫 | Standard Library | C 語言環境提供的標準功能集合。 |

## 資料、流程與函數

| 中文 | 英文 | 使用說明 |
|---|---|---|
| 值 | Value | 程式處理的資訊內容。 |
| 型別 | Type | 約束資料表示、範圍與可用操作。 |
| 變數 | Variable | 以名稱指涉可改變狀態的資料實體。 |
| 常數 | Constant | 在指定語意範圍內不應改變的值。 |
| 運算式 | Expression | 可被求值的值、名稱與運算子組合。 |
| 指定 | Assignment | 將結果寫入資料位置並改變狀態。 |
| 狀態 | State | 某一執行時刻程式中的資料情況。 |
| 順序 | Sequence | 敘述依時間次序執行。 |
| 條件 | Condition | 由目前資料產生真假判定。 |
| 選擇 | Selection | 根據條件決定執行路徑。 |
| 重複 | Repetition | 在條件與狀態更新下反覆執行。 |
| 終止條件 | Termination Condition | 決定重複何時停止的條件。 |
| 函數 | Function | 封裝一項具名責任的可呼叫單位。 |
| 參數 | Parameter | 函數介面宣告的輸入名稱。 |
| 引數 | Argument | 呼叫函數時實際提供的值或運算式。 |
| 回傳值 | Return Value | 函數透過介面交還呼叫者的結果。 |
| 作用域 | Scope | 名稱可以被使用的程式區域。 |
| 生命週期 | Lifetime | 資料實體存在並有效的時間範圍。 |
| 模組化 | Modularization | 以明確介面組織相關責任與實作。 |
| 遞迴 | Recursion | 函數直接或間接呼叫自身的問題表達方式。 |

## 記憶體與資料組織

| 中文 | 英文 | 使用說明 |
|---|---|---|
| 儲存位置 | Storage Location | 資料實體所在的記憶體區域。 |
| 位址 | Address | 識別儲存位置的值。 |
| 指標 | Pointer | 儲存位址的具型別變數。 |
| 取址 | Address-of | 取得物件位址的操作。 |
| 解參考 | Dereference | 透過位址存取目標物件的操作。 |
| 別名 | Alias | 多個名稱或指標指向同一資料位置的關係。 |
| 自動儲存期 | Automatic Storage Duration | 通常與區塊及函數呼叫生命週期相關的儲存期。 |
| 動態儲存期 | Dynamic Storage Duration | 執行期間依需求配置與釋放的儲存期。 |
| 呼叫堆疊 | Call Stack | 保存函數呼叫與返回資訊的執行結構。 |
| Heap | Heap | 本課程保留英文詞，指動態配置常用的記憶體區域模型；避免翻成「堆」而與資料結構混淆。 |
| 序列 | Sequence | 依位置或順序組織的多個元素。 |
| 索引 | Index | 透過位置或鍵定位資料的方法。 |
| 字串 | String | 以字元序列表示的文字資料。 |
| 記錄 | Record | 將描述同一實體的多個欄位組合。 |
| 結構 | Structure / `struct` | C 語言中建立記錄型資料的語法與型別機制。 |
| 搜尋 | Search | 找出符合條件資料的操作。 |
| 重新排列 | Rearrangement | 依規則改變元素順序；具體排序演算法不一定是目前核心。 |

## 測試、除錯與 AI

| 中文 | 英文 | 使用說明 |
|---|---|---|
| 預期結果 | Expected Result | 執行前依需求推導的結果。 |
| 實際結果 | Actual Result | 執行後觀察到的結果。 |
| 測試案例 | Test Case | 具體描述輸入、條件與預期結果。 |
| 正常案例 | Normal Case | 驗證一般使用情境。 |
| 邊界案例 | Boundary Case | 驗證臨界值、範圍與轉折位置。 |
| 異常案例 | Exceptional Case | 驗證不合法或非預期輸入；僅在適用時要求。 |
| 執行追蹤 | Execution Trace | 逐步記錄資料、控制、呼叫或記憶體變化。 |
| 除錯 | Debugging | 以證據重現、縮小範圍、形成並驗證假設。 |
| 回歸測試 | Regression Testing | 確認修正未破壞原本正確行為。 |
| AI 輔助學習 | AI-assisted Learning | 使用 AI 協助理解、提示、測試與除錯，但不取代核心思考。 |
| 人工審查 | Human Review | 由學習者或教師檢查 AI 建議的適切性。 |
| 技術驗證 | Technical Verification | 透過文件、編譯、執行、追蹤與測試確認主張。 |
| AI 使用紀錄 | AI-use Record | 記錄目標、當時狀態、建議摘要、驗證、決策與理由。 |

## 維護與完成標準

本術語表視為完成，必須同時符合：

- 中英文版本存在且實質一致。
- 每個正式教材與評量使用一致術語。
- 新增術語包含定義或使用說明。
- 容易混淆的術語具有明確區分。
- 變更可透過 Git commit、Issue 或 PR 追蹤。
