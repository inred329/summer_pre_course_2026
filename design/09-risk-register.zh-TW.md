# 課程風險登錄表

版本：0.1.0  
狀態：架構草案  
對應英文版本：[Course Risk Register](09-risk-register.en.md)

## 文件目的

本文件辨識、評估並管理 2026 暑期前導課程與後續 16 週正式 C 程式設計課程的主要設計與執行風險。

它回答：

1. 哪些因素可能破壞課程願景、能力發展或驗收可信度？
2. 風險何時可能發生，如何被提早偵測？
3. 哪些預防措施應在課程開始前完成？
4. 風險發生時應採取哪些應變措施？
5. 哪些風險即使緩解後仍需持續觀察？

本文件不是一般行政待辦清單。風險必須能追溯到需求、能力、範圍、驗收或交付設計，並指定可觀察觸發條件與責任角色。

## 憲法遵循

- 理解、驗證與學生責任優先於表面進度與產出數量。
- 中文班與英文班的核心標準不得因執行壓力而分岔。
- AI 相關風險以改善學習設計為優先，不以全面禁止取代治理。
- 風險處理不得透過加入更多內容、降低驗收要求或偷渡進階資料結構解決。
- 任何重大範圍變更都必須同步更新正式設計文件。

# 一、風險評估模型

## 1.1 發生機率

| 等級 | 定義 |
|---|---|
| P1 低 | 在目前條件下不太可能發生，但仍需觀察。 |
| P2 中 | 有合理可能發生，需安排預防與監測。 |
| P3 高 | 很可能發生，必須在課程開始前採取措施。 |

## 1.2 影響程度

| 等級 | 定義 |
|---|---|
| I1 低 | 影響單一活動或少數學生，可在原節奏內修正。 |
| I2 中 | 影響一個交付階段、班級一致性或多項證據。 |
| I3 高 | 破壞核心能力、驗收可信度、課程銜接或憲法原則。 |

## 1.3 優先級

```text
風險分數 = 發生機率 × 影響程度
```

| 分數 | 優先級 | 處理要求 |
|---:|---|---|
| 1–2 | 低 | 記錄並週期性檢查。 |
| 3–4 | 中 | 必須有預防措施、觸發條件與責任角色。 |
| 6–9 | 高 | 課程開始前完成主要緩解，並設置明確應變方案。 |

數字只用於排序，不能取代專業判斷。任何涉及學生安全、公平或核心驗收失真的風險，即使分數較低，也可提升為高優先。

# 二、風險狀態與責任

| 狀態 | 定義 |
|---|---|
| Open | 已辨識，尚未完成主要緩解。 |
| Mitigating | 正在執行預防或降低措施。 |
| Watching | 主要措施已完成，持續觀察觸發指標。 |
| Triggered | 風險已發生，正在執行應變方案。 |
| Closed | 風險已消失、被接受，或已轉化為其他正式決策。 |

責任角色：

- 課程負責教師：範圍、能力、驗收與重大調整的最終責任。
- 授課教師：課堂節奏、學習證據、現場調整與風險回報。
- 助教：觀察學習落差、協助驗收、記錄重複問題與異常模式。
- 教材維護者：雙語一致、導覽、版本與教材缺陷修正。
- 學生：提出真實學習證據、揭露 AI 使用並參與補驗。

同一人可以兼任多個角色，但每項風險仍需指定主要責任角色。

# 五、監測指標

每個班別至少在每個交付階段檢查下列指標：

| 指標 | 可能代表的風險 |
|---|---|
| 只通過程式但無法解釋或追蹤的學生比例 | R-01、R-05、R-06 |
| 被取消或縮短的追蹤、測試、口試活動數 | R-02、R-05、R-15 |
| 中文班與英文班核心任務或通過率差異 | R-03、R-10、R-12 |
| 前導與正式課程活動重複比例 | R-04 |
| 工具問題占用課堂時間 | R-08、R-18 |
| 補驗集中在哪些能力 ID | R-02、R-06、R-09 |
| AI 建議未經驗證即採用的比例 | R-01、R-14 |
| 正式文件中斷鏈、舊 ID 或雙語不一致數量 | R-10、R-17 |
| 新增未經範圍審查的主題數 | R-07、R-17 |

指標用於判斷系統問題，不應被用來公開標記或羞辱個別學生。

# 六、風險處理策略

| 策略 | 適用情況 |
|---|---|
| Avoid 避免 | 移除會直接違反範圍或憲法的設計，例如把進階資料結構列為核心。 |
| Reduce 降低 | 透過支架、練習、環境標準化與多元證據降低機率或影響。 |
| Transfer 轉移 | 將非教學核心的技術支援交由助教、文件或備援環境處理。 |
| Accept 接受 | 風險成本低、無法完全消除，且已建立監測與應變。 |

不能接受的處理方式：

- 為了趕進度取消測試、追蹤、除錯或口試。
- 以更多題目取代更好的證據。
- 以全面禁止 AI 取代 AI 素養與驗證設計。
- 以降低英文班核心標準解決語言負荷。
- 以新增進階主題處理高能力學生的等待時間。

# 七、風險審查節奏

## 課程開始前

- 確認環境、教材、雙語版本與導覽。
- 以範例校準教師與助教的成熟度判定。
- 確認每個核心能力具備互補證據。
- 檢查前導與正式課程是否存在不必要重複。

## 每個交付階段後

- 檢查觸發條件與監測指標。
- 更新風險狀態、措施與殘餘風險。
- 只調整節奏與支架，不在未經審查時擴張範圍。

## 課程結束後

- 比較預期與實際風險。
- 記錄哪些措施有效、哪些造成新問題。
- 將重大發現回寫需求、範圍、驗收與交付文件。

# 八、完成條件

本風險登錄表完成後，後續設計必須能：

- 將每項重大風險連結到需求、能力、範圍、驗收或交付決策。
- 指出可觀察的觸發條件，而不是只列抽象擔憂。
- 指定預防措施、應變方案與責任角色。
- 在不降低核心標準的前提下處理時數、語言、工具與 AI 壓力。
- 為下一份[追蹤矩陣](10-traceability-matrix.zh-TW.md)提供風險 ID。
