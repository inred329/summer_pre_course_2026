# 教學內容設計區

版本：0.4.0  
狀態：規劃中  
對應英文版本：[Instructional Design Workspace](README.en.md)

## 文件目的

本目錄用來以軟體專案的需求工程方式設計 2026 暑期 C 語言前導課程與後續 16 週正式課程。

課程設計不先從週次、投影片或教材章節開始，而是依序定義：

1. 教育願景與問題。
2. 利害關係人及其需求。
3. 程式語言的完整知識空間與概念依賴。
4. 學生完成課程後應具備的能力及成熟度。
5. 前導課程與正式課程的範圍邊界。
6. 可觀察、可驗收的學習證據。
7. 中文班與英文班的交付節奏。
8. 教材、活動、作業與評量。

## 憲法遵循

本目錄內所有正式文件，在撰寫、修改或翻譯前，均須先參考：

- [課程憲法（繁體中文）](../CONSTITUTION.zh-TW.md)
- [Course Constitution (English)](../CONSTITUTION.en.md)

每份文件至少必須符合下列原則：

- 促進學生真正理解，而非只完成產出。
- 中文版與英文版必須成對建立並實質一致。
- 每項能力必須具備明確的先備條件與驗收方式。
- 內容應控制初學者的認知負荷。
- 閱讀、修改、測試、除錯與解釋，與從零撰寫同樣重要。
- 可視覺化的概念與關係應提供適當圖形。
- AI 只能協助學習，不得取代核心思考責任。
- 前導課程與正式課程必須形成連續而非重複的能力發展。
- 所有正式文件必須由根 README 經直接或間接導覽鏈抵達。

## 工作順序

1. 確立產品願景與成功定義。
2. 建立需求地圖。
3. 建立程式語言知識圖。
4. 將知識節點轉換為可觀察、可驗收的能力地圖。
5. 定義前導課程、正式課程與延後內容的範圍邊界。
6. 建立能力驗收模型。
7. 將共同能力組成中文班與英文班不同節奏。
8. 最後才製作逐堂教案與教材。

## 目前核心假設

- 教學語言為 C 語言，但核心目標是程式設計能力與 C 的語言邏輯。
- 每個概念均應依「需求 → 設計目的 → 語言邏輯 → 語法 → 實作 → 驗證」展開。
- 程式設計以資料與狀態、流程與控制、函數與抽象為基本支柱。
- 程式轉換與執行、記憶體模型、資料組織、測試除錯與 AI 素養為必要知識面向。
- 能力成熟度依學生可觀察行為區分為辨識、解釋、追蹤、實作、診斷與遷移。
- 範圍狀態區分為核心交付、基礎鋪墊、延後深化、延後實作與課程外。
- 英文前導班共 5 堂，每堂 2 小時，共 10 小時。
- 中文前導班共 4 堂，每堂 3 小時，共 12 小時。
- 正式課程共 16 週，每週 3 小時，共 48 小時。
- 兩個前導班的共同核心學習成果必須一致；額外 2 小時不得用來造成核心能力差距。
