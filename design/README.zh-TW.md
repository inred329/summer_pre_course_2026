# 教學內容設計區

版本：0.1.0  
狀態：規劃中  
對應英文版本：`README.en.md`

## 文件目的

本目錄用來以軟體專案的需求工程方式設計 2026 暑期 C 語言前導課程與後續 16 週正式課程。

課程設計不先從週次、投影片或教材章節開始，而是依序定義：

1. 教育願景與問題。
2. 利害關係人及其需求。
3. 學生完成課程後應具備的能力。
4. 能力之間的依賴關係。
5. 可觀察、可驗收的學習證據。
6. 前導課程與正式課程的範圍邊界。
7. 中文班與英文班的交付節奏。
8. 教材、活動、作業與評量。

## 憲法遵循

本目錄內所有正式文件，在撰寫、修改或翻譯前，均須先參考：

- `../CONSTITUTION.zh-TW.md`
- `../CONSTITUTION.en.md`

每份文件至少必須符合下列原則：

- 促進學生真正理解，而非只完成產出。
- 中文版與英文版必須成對建立並實質一致。
- 每項能力必須具備明確的先備條件與驗收方式。
- 內容應控制初學者的認知負荷。
- 閱讀、修改、測試、除錯與解釋，與從零撰寫同樣重要。
- AI 只能協助學習，不得取代核心思考責任。
- 前導課程與正式課程必須形成連續而非重複的能力發展。

## 專案類比

| 軟體專案 | 課程設計 |
|---|---|
| 產品願景 | 教育願景 |
| 使用者需求 | 學生與教師需求 |
| 功能需求 | 學習成果與能力需求 |
| 非功能需求 | 公平、雙語、可維護性與認知負荷 |
| 架構與依賴 | 能力地圖與先備知識 |
| MVP | 前導課程最低可行準備能力 |
| 正式版本 | 16 週正式 C 語言課程 |
| 驗收條件 | 可觀察的學習證據 |
| 測試案例 | 練習、口頭說明、修改題與評量 |
| 缺陷 | 學習迷思與理解斷點 |
| 追蹤矩陣 | 目標、能力、教材與評量的對應關係 |

## 工作順序

1. 確立產品願景與成功定義。
2. 建立需求地圖。
3. 建立完整 C 語言能力地圖。
4. 定義正式課程的最終交付能力。
5. 反向切出前導課程的 MVP 範圍。
6. 將共同能力組成中文班與英文班不同節奏。
7. 最後才製作逐堂教案與教材。

## 目前核心假設

- 教學語言為 C 語言，但核心目標是程式設計能力。
- 程式設計可先以三個核心支柱組織：資料與變數、流程控制、函數與分解。
- 程式執行模型、輸入輸出、測試、除錯與 AI 素養為橫向能力。
- 英文前導班共 5 堂，每堂 2 小時，共 10 小時。
- 中文前導班共 4 堂，每堂 3 小時，共 12 小時。
- 正式課程共 16 週，每週 3 小時，共 48 小時。
- 兩個前導班的共同核心學習成果必須一致；額外 2 小時不得用來造成核心能力差距。
