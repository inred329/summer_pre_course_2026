# 程式設計能力地圖

版本：0.2.0  
狀態：架構草案  
對應英文版本：[Programming Competency Map](05-competency-map.en.md)

## 文件目的

本文件將[程式設計領域模型](03-programming-domain-model.zh-TW.md)與[程式語言知識依賴圖](04-programming-language-knowledge-graph.zh-TW.md)轉換為可觀察、可教學與可驗收的學生能力。

- 領域模型回答「有哪些概念與關係」。
- 知識依賴圖回答「理解某概念前通常需要什麼」。
- 能力地圖回答「學生實際要能做到什麼」。

本文件不是週次表，也不是評分規準。後續範圍邊界、驗收模型、課程節奏、教材與評量均應引用本文件的能力識別碼。

## 憲法遵循

- 能力完成不能只以成功執行或通過測試判定。
- 能力敘述必須具體、可觀察、可執行。
- 中文版與英文版使用相同識別碼、成熟度與實質要求。
- 能力依賴與心智模型在適當時提供視覺表示。
- AI 可協助解釋、提示、測試與除錯，但不得取代理解、設計、追蹤與驗證責任。
- 本文件不預先把進階資料結構列為 C 課程核心能力。

# 一、能力成熟度模型

```mermaid
flowchart LR
    L1[L1 辨識 Recognize] --> L2[L2 解釋 Explain]
    L2 --> L3[L3 追蹤 Trace]
    L3 --> L4[L4 實作 Implement]
    L4 --> L5[L5 診斷 Diagnose]
    L5 --> L6[L6 遷移 Transfer]
```

| 等級 | 名稱 | 可觀察行為 |
|---|---|---|
| L0 | 尚未建立 | 無法可靠辨識概念，或僅能猜測與模仿。 |
| L1 | 辨識 | 能在範例中指出概念、語法、資料或執行階段。 |
| L2 | 解釋 | 能用自己的話說明存在原因、核心邏輯與基本作用。 |
| L3 | 追蹤 | 能逐步預測執行、資料狀態、控制路徑或記憶體變化。 |
| L4 | 實作 | 能依需求選擇並正確使用能力完成小型任務。 |
| L5 | 診斷 | 能設計測試、定位錯誤、說明原因並完成合理修改。 |
| L6 | 遷移 | 能在新情境、較大問題或其他語言中辨識相同邏輯並調整做法。 |

重要能力原則上至少需要一項解釋或追蹤證據，以及一項實作、修改或診斷證據。

# 二、共同學習證據

| 證據代碼 | 類型 | 學生必須展現的內容 |
|---|---|---|
| EV-EX | 解釋 | 用自己的話說明需求、設計目的、語言邏輯與程式行為。 |
| EV-VI | 視覺表示 | 畫出並解讀流程、狀態、記憶體、函數呼叫或資料組織。 |
| EV-TR | 執行追蹤 | 逐步記錄變數值、控制路徑、函數呼叫或記憶體變化。 |
| EV-IM | 實作 | 依需求完成符合目前範圍的小型程式或片段。 |
| EV-MO | 修改 | 面對需求變更修改既有程式並說明受影響部分。 |
| EV-TE | 測試 | 建立預期結果、正常案例、邊界案例及必要異常案例。 |
| EV-DE | 除錯 | 重現問題、縮小範圍、提出假設、驗證假設並說明修正。 |
| EV-CO | 比較 | 比較兩種寫法、解法或工具輸出並說明取捨。 |
| EV-AI | AI 判斷 | 說明 AI 建議、驗證方法及採用、修改或拒絕理由。 |
| EV-RE | 反思與遷移 | 說明能力如何應用到新問題、後續主題或其他語言。 |

任何正式評量不得只使用 EV-IM 或自動測試通過作為唯一證據。

## 使用原則

1. 能力地圖不直接決定週次。
2. 前導與正式課程的成熟度邊界由下一份範圍文件決定。
3. 新增能力前，必須能追溯至領域模型概念與知識依賴。
4. 不得因追求主題數量而降低測試、除錯、解釋與 AI 驗證要求。
5. 進階資料結構若未來要納入，必須另行提出需求、先備、時數與驗收證據，不得默認加入。
