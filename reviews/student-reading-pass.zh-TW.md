# 學生閱讀體驗審查｜Student Reading Pass

版本：0.7.0  
最後更新：2026-08-09  
對應英文版本：[Student Reading Pass](student-reading-pass.en.md)

## 審查目的

這份紀錄追蹤學生教材的實際閱讀體驗。審查時不以文件治理或規範符合性為主，而是把每一個 Unit 從頭讀到尾，觀察學生是否能自然跟上敘事、概念與操作。

每一個 Unit 都檢查：

- 開頭是否能快速建立問題與動機。
- 概念與名詞是否在需要時才出現，且有足夠鋪陳。
- 段落之間是否有自然的因果或學習銜接。
- 範例、錯誤案例與練習是否真的幫助理解，而不是只增加清單。
- 是否混入不必要的內部治理、評量或文件邊界語氣。
- 結尾是否能自然銜接下一個 Unit。
- 中英文是否維持相同的學習路徑與技術含義。

## P-U01 閱讀觀察

原版本技術內容完整，但開頭先出現「文件用途與完成標準」、提交與 AI 規則，學生在遇到第一個程式問題之前就先讀到文件治理語氣。中後段也有數個以「限制」「建議保留紀錄」「測試表」呈現的區塊，容易讓教材像操作規格，而不是一條連續的學習故事。

第一輪修正後，P-U01 改成直接從「儲存 C 文字檔後到底發生什麼」切入；每個概念都回到同一個 `hello.c` 實驗，並用預測、實際操作、故意製造錯誤與修改需求串起整章。中英文的章節順序、問題、實驗與收尾保持實質等值。

## P-U02 閱讀觀察

原版本開頭同樣先放置完成標準、保存紀錄與 AI 規則，延遲了學生真正遇到「程式怎麼記住資料」的核心問題。更重要的是，章中在尚未正式介紹控制流程以前就出現 `if`，並在需求修改中要求學生實作「最高 100 分」規則，使讀者必須先使用下一 Unit 才會學到的條件判斷。

第一輪修正後，P-U02 從 P-U01 的固定輸出自然轉向「程式執行後內部會留下什麼」，用 `score = score + 5` 建立值、型別、變數、指定與狀態。輸入範例仍保留安全的成功檢查，但明確告訴學生 `if` 與 `&score` 目前只需理解用途，不要求提早掌握語法。原本要求立即實作 100 分上限的段落改成一個刻意留下的失敗需求：學生先看見 `98 + 5` 會得到 `103`，再自然產生「程式怎麼選擇不同路徑」的需求，直接銜接 P-U03。

## P-U03 閱讀觀察

原版本一開始再次出現文件用途、完成標準、保存紀錄與 AI 規則，然後才進入控制流程；內容本身雖完整，但「條件、比較運算子、迴圈四要素、錯誤案例、練習」多以並列章節出現，和 P-U02 最後留下的 100 分上限問題沒有真正接起來，因此學生容易把它讀成下一批新語法與清單。

第一輪修正後，P-U03 直接從 `98 + 5 = 103` 的失敗需求開始，先用 `if (final_score > 100)` 解決一個學生已經有動機理解的問題，再由 99、100、101 建立邊界觀念。之後才擴展到 `else`、比較與邏輯組合、輸入成功檢查和多分支順序。迴圈則從「1 加到 5」的重複需求引出，持續回到狀態、條件、工作與更新四件事；off-by-one 與無窮迴圈也改成從「哪一輪消失」與「狀態是否往終止方向改變」來診斷。章末自然銜接到 P-U04 的問題：當所有責任都塞進 `main`，程式開始難讀、難改、難驗證。

## P-U04 閱讀觀察

原版本雖然很清楚地想建立「分離責任」的觀念，但第一個完整函數範例就同時要求學生理解 `int *result`、`NULL`、`INT_MAX`、`INT_MIN`、有號溢位檢查、狀態回傳，以及透過指標輸出結果。這些都是正式課程值得深入處理的內容，但前導課程此時還沒有正式建立指標與整數邊界的心智模型，因此學生還沒舒服地理解「一次函數呼叫到底發生什麼、回傳值去了哪裡」，就得先吸收好幾個更進階的介面機制。開頭也仍然先放文件用途與完成標準，沒有直接承接 P-U03 留下的問題。

第一輪修正後，P-U04 從 P-U03 的最後一個困難直接開始：程式已經會保存狀態、選擇與重複，但所有責任都留在 `main` 時會越來越難讀。先用 `max_of_two` 建立函數名稱、參數、引數、呼叫流程與直接回傳值，再用一個很小的追蹤把值從呼叫者送進函數、再送回來。介面契約改以刻意限制範圍的成績資料介紹，因此能討論「呼叫者必須保證什麼」，又不需要把輸出指標與溢位保留機制塞進前導主線。整合故事則改成三次小考的成績報告器：輸入與驗證清楚留在 `main`，平均計算與及格判斷變成可單獨命名、直接測試的函數。章末也明確收束前導課程，並從學生已經多次使用的 `int`、`double`、算術與輸入，提出下一個正式課程問題：這些操作背後其實依賴表示方式、型別規則與邊界行為，因而自然銜接 F-U01。

## F-U01 閱讀觀察

原版本在技術上已經涵蓋位元、MSB／LSB、型別、整數除法、浮點近似、溢位、字元與格式不匹配，但閱讀路徑仍以「文件用途與完成標準 → 核心問題 → 能力清單 → 一系列主題章節 → 錯誤案例 → 練習」為主。學生剛從 P-U04 建立完函數與資料流，就先遇到治理式完成標準與抽象概念清單，沒有立刻看見為什麼已經熟悉的 `int`、`double` 值得重新深挖。格式不匹配、浮點比較與有號溢位也分散出現，缺少一個能幫學生區分「合法但不符合需求」和「語言已不保證行為」的共同診斷框架。

第一輪修正後，F-U01 直接接住 P-U04 的收尾，以 `double result = 5 / 2;` 會得到 `2.0` 的具體意外開始，讓學生先有問題，再逐步建立「值 → 表示 → 型別 → 運算時機 → 格式契約 → 近似 → 邊界」的閱讀主線。MSB／LSB 只先用無號二進位建立位置與權重，避免提前把 MSB 誤背成固定符號位元；`printf` 格式則被放回型別契約脈絡，不再只是孤立的錯誤案例。浮點章節特別區分「計算近似值通常需要容許誤差」和「規格刻意使用精確 `0.0` 哨兵時可直接比較」，避免把規則簡化成「浮點永遠不能 `==`」。整數邊界則用「先檢查、再運算」建立安全順序，並把有號溢位、無號模數運算、整數除法與格式不匹配整理成 defined-vs-undefined 的診斷表。章末以一個 `unsigned int`／`double` 報告器串起輸入格式、十進位／十六進位表示、除法、零除數與邊界測試，再自然把注意力轉向 F-U02：當多個條件與狀態開始互相影響，下一步需要追蹤的是更複雜的控制流程。

## F-U02 閱讀觀察

原版本的個別主題都正確，但閱讀上仍然很像「文件用途與完成標準 → 能力清單 → 多分支 → `switch` → 巢狀 → sentinel → invariant → 錯誤案例 → 練習」的並列教材。學生從 F-U01 進來時，沒有先看見「值已經會被正確解讀，現在真正困難的是它會讓程式走哪條路」這個承接；sentinel、EOF、無效輸入與 invariant 也在較短篇幅內快速連續出現，容易變成新名詞堆疊。

第一輪修正後，F-U02 直接從 F-U01 的值與規則延伸成「值決定路徑」。先用成績分類讓學生親眼看到 `if`／`else if` 的順序本身就是規則，再用 69／70、79／80、89／90 建立邊界測試。`switch` 被放在「離散選擇」的比較脈絡中；巢狀條件則改用可到達路徑表理解。之後才從「不知道會輸入幾筆資料」自然引出重複流程與 sentinel，並用三條具體輸入路徑區分 sentinel、EOF 與無效文字。Loop invariant 不再先要求背定義，而是用初始化、維持、終止三個問題說明「每輪都不能被破壞的事實」。錯誤案例也回到被破壞的路徑或狀態規則來診斷。最後以未知筆數平均與「忽略超出範圍值」的需求修改，讓檢查順序、sentinel、invariant 與回歸測試在同一個問題裡重新出現，並自然引出 F-U03：當資料不只逐筆處理，而是要同時保留許多同型資料時，就需要陣列。

## F-U03 閱讀觀察

原版本的陣列基本概念清楚，但仍以完成標準與能力清單開場，沒有直接接住 F-U02「逐筆處理」留下的限制。更大的閱讀跳躍出現在 `max_array`：學生才剛建立陣列、索引與長度，就立刻遇到 `int *result`、`NULL`、輸出參數與空指標契約；完整指標模型要到 F-U06 才建立，這使「安全找最大值」反而要求尚未具備的概念。越界、未初始化、空集合也較像獨立錯誤清單，沒有回到同一個「這一格能不能合法讀取」模型。

第一輪修正後，F-U03 從 F-U02 的未知筆數處理直接提出新需求：如果多筆資料要同時保留並重複分析，只留 `sum`／`count` 就不夠。以五筆成績的索引圖建立陣列、元素、索引與長度，再把 F-U02 已熟悉的迴圈控制變數變成陣列位置，讓 `i < length` 的邊界規則自然出現。越界與未初始化被統一成兩個不同前提：「位置是否合法」與「該位置是否已有有效資料」。函數段保留「陣列＋長度」介面，但明確把陣列參數與指標的底層關係延後到 F-U06；`max_array` 改成直接回傳最大值並要求 `length > 0`，由呼叫端先處理空集合，避免過早引入輸出指標與 `NULL`。最後用十人成績分析器、可證明的累加範圍與「去掉最低分」需求修改，把輸入驗證、走訪、邊界與重新分析放回同一條故事，並以「字串就是具有終止規則的字元陣列」銜接 F-U04。

## 完成條件

Student Reading Pass 只有在 P-U01～P-U04 與 F-U01～F-U12 全部完成逐篇閱讀，主要閱讀阻礙已修正，而且學生不需要依賴 design、reviews 或其他內部文件才能理解教材時才算完成。
