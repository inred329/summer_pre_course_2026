# 全庫 Constitution 2.0 符合性審查

版本：0.1.0  
狀態：審查基準草案  
權威基準：`CONSTITUTION.zh-TW.md` 2.0.0  
主要讀者：課程設計者、授課教師與維護者  
規範效力：本文件只記錄審查結果與修正建議，不自行建立新規範

## 一、審查目的

本審查依 Constitution 2.0 重新檢視本倉庫所有正式文件，目標不是一次改寫所有內容，而是建立一套可追蹤、可排序、可逐批完成的修正程序。

審查必須回答：

1. 文件屬於哪一個治理層級。
2. 文件的主要讀者是誰。
3. 文件是否有明確且唯一的權威角色。
4. 中英文版本是否完整且實質等值。
5. 學生文件是否符合閱讀權與教學原則。
6. 技術內容是否可驗證。
7. AI、評量與雙語班規範是否符合 Constitution 2.0。
8. 文件應保留、改寫、移動、合併、降級為歷史紀錄或刪除。

## 二、審查原則

### 1. 憲法不是檢核表的替代品

Constitution 2.0 只提供最高原則。具體格式、模板與流程必須由 Standards、Guides 或 Policies 承接。審查不得把新的操作細節偷偷寫成憲法要求。

### 2. 學生文件優先

學生教材的問題優先於內部治理文件的整齊度。任何會妨礙學生持續閱讀、建立理解或驗證概念的問題，均列為高優先修正。

### 3. 不以存在代替有效性

文件存在於版本控制中，不表示它仍是有效、可發布或適合作為權威來源。過時審查、重複政策與未被導覽的文件都必須重新判定角色。

### 4. 審查文件不建立新規範

所有修正必須回寫至真正的權威來源。審查報告只記錄證據、判斷與建議。

## 三、文件分類模型

每份文件先歸入以下層級之一：

| 層級 | 目的 | 常見內容 |
|---|---|---|
| Constitution | 不可妥協且長期穩定的原則 | 最高目的、裁決原則、治理邊界 |
| Standards | 一致性要求與品質基準 | 文件類型、寫作標準、模板、metadata、導覽標準 |
| Guides and Policies | 可調整的流程與當期規則 | 評量政策、授課流程、發布流程、技術驗證方式 |
| Materials | 實際教學與學習內容 | 學生教材、教師指南、課程活動、程式範例 |
| Historical Record | 只保留決策與演進證據 | 已完成審查、舊版遷移報告、歷史決策紀錄 |

每份正式文件必須有一個主要讀者：學生、教師、設計／維護者或審查者。

## 四、符合性判定

### A — 符合

文件角色清楚，符合主要讀者需要，雙語與技術內容無重大問題。

### B — 小幅修正

核心內容可保留，但需要改善導覽、用詞、邊界、metadata 或局部同步。

### C — 結構性修正

文件仍有價值，但主要讀者混雜、權威來源不清、學生閱讀品質不足，或與其他文件重複定義規範。

### D — 不符合

文件與 Constitution 2.0 明顯衝突、已過時、錯誤引用舊憲法、技術不可驗證，或對學生造成重大閱讀與理解障礙。

### H — 歷史化

文件不再作為現行規範，但值得保留為演進或決策證據。必須清楚標示歷史狀態，且不得被現行導覽誤認為有效政策。

## 五、風險優先順序

### P0 — 立即修正

- 錯誤或過時的最高規範、政策與評量要求。
- 學生可能直接讀到的技術錯誤或重大誤導。
- 中英文要求實質衝突。
- 權威來源互相矛盾。

### P1 — 高優先

- 學生教材難以連續閱讀。
- 教師文件與學生教材混雜。
- AI 規則仍強制要求紀錄、聲明或使用。
- 學習依賴順序錯誤。
- 重要程式碼與說明無法驗證。

### P2 — 中優先

- README 與索引無法讓主要讀者合理抵達文件。
- 文件類型或主要讀者不清。
- 重複政策、重複定義或過度 metadata。
- 審查文件尚未歷史化。

### P3 — 一般改善

- 編排、術語、格式與輕微雙語差異。
- 不影響理解與決策的維護品質問題。

## 六、初步全庫盤點結論

根據目前倉庫結構，應優先審查以下群組：

### 第一批：權威來源與導覽

- 根目錄 `README.md`
- `CONSTITUTION.zh-TW.md`
- `CONSTITUTION.en.md`
- `classes/zh/README.md`
- `classes/en/README.md`
- `design/13-learning-assessment-policy.*`
- 所有仍引用 Constitution 1.3.0 或舊 AI 規則的文件

目的：確認 2.0 已成為唯一最高基準，移除重複或過時規則，建立學生、教師、設計維護者的清楚入口。

### 第二批：學生學習材料

- 所有 Units 的學生教材
- 學生課程導覽、作業與評量說明
- 學生會直接閱讀的程式範例與環境文件

目的：優先檢查通順性、段落承接、Concept-first、依賴順序、錯誤與驗證、內部治理污染，以及技術正確性。

### 第三批：教師文件

- Unit 教師指南
- 課堂執行流程
- 觀察、提問、常見誤解與備案文件

目的：確認教師文件可執行但不重寫學生教材，也不把教師提示提前暴露給學生。

### 第四批：設計與治理文件

- `design/01` 至後續設計文件
- Concept Tree、Registry、Unit Map、Traceability Matrix
- Terminology、Scope、Acceptance、Risk 與 Delivery 文件

目的：確認權威角色、相互依賴、重複定義與是否應移入 Standards、Policies 或 Historical Record。

### 第五批：審查與歷史文件

- `design/12-constitution-compliance-review.*`
- `reviews/constitution-maturity-review.*`
- 其他已完成的 audit、review 與 validation 文件

目的：標示審查基準與日期，將舊憲法審查歷史化，避免被誤認為現行規範。

### 第六批：技術驗證與自動化

- `.github/workflows/technical-validation.yml`
- 所有程式碼範例與編譯清單
- 連結、雙語配對與導覽完整性檢查

目的：讓可自動驗證的部分由 CI 負責，但不把可讀性與教學品質交給自動化判定。

## 七、每份文件的審查欄位

後續矩陣至少記錄：

| 欄位 | 說明 |
|---|---|
| Path | 文件路徑 |
| Language Pair | 對應語言版本 |
| Governance Level | Constitution / Standards / Guides and Policies / Materials / Historical Record |
| Primary Audience | 學生 / 教師 / 設計維護者 / 審查者 |
| Authoritative Role | 是否為某項規範的唯一權威來源 |
| Constitution Articles | 涉及條文 |
| Rating | A / B / C / D / H |
| Priority | P0 / P1 / P2 / P3 |
| Findings | 具體問題與證據 |
| Action | 保留 / 改寫 / 移動 / 合併 / 歷史化 / 刪除 |
| Validation | 雙語、技術、導覽與人工審查方式 |

## 八、第一輪已知風險

1. `design/12-constitution-compliance-review.*` 是依舊版憲法產生的審查，可能不再適合作為現行符合性結論，應優先歷史化或重寫。
2. 根 README 可能仍以舊文件架構作完整索引，而不是依主要讀者提供入口。
3. 現有 design 文件數量多且可能同時扮演 Standards、Policies、Review 與 Historical Record，權威邊界需要重新劃分。
4. 學生教材雖已技術驗證，但仍需依第六條做人工閱讀品質審查；CI 通過不能證明文章通順。
5. 評量政策與各 Unit 內的 AI、作業、提交與評量說明可能存在重複定義，必須回歸單一權威來源。

## 九、執行方式

全庫修正分為多個小型 PR，不在單一 PR 中同時重寫所有文件：

1. PR A：導覽、文件分類與權威來源。
2. PR B：評量與 AI 政策一致性。
3. PR C：學生教材閱讀品質，按 Unit 批次進行。
4. PR D：教師文件邊界與可執行性。
5. PR E：設計文件治理層級與歷史化。
6. PR F：CI、雙語配對、連結與技術驗證補強。

每個 PR 必須同步處理中英文版本，並指出其依據的 Constitution 2.0 條文。

## 十、本輪結論

Constitution 2.0 已成為唯一正式基準。下一步不應立即對所有文件做無差別重寫，而應先完成權威來源與文件角色盤點，再按照 P0 至 P3 分批修正。

本文件是全庫審查的工作基準，不是新的憲法或政策來源。
