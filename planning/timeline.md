# 課程籌備時程

版本：0.2.0  
狀態：現行操作規劃模型  
最後更新：2026-08-07  
主要讀者：授課教師、助教、行政與課程維護者  
規範效力：本文件只規劃開課前後的操作節點，不自行建立能力、範圍、評量、完課或 AI／工具政策

## 使用方式

以下仍以正式開課日為 `T` 倒推。實際日期確定後，可把相對週期換成日曆日期；但課程內容與評量不得因排程壓力在此被重新定義。

現行課程設計、中文／英文班節奏與正式評量規則分別以 [design 治理索引](../design/README.zh-TW.md)、[課程交付地圖](../design/08-delivery-map.zh-TW.md)與[學習與評量制度](../design/13-learning-assessment-policy.zh-TW.md)為準。

| 時間 | 操作里程碑 | 主要確認事項 |
|---|---|---|
| T-12～10 週 | 行政條件確認 | 日期候選、場地／線上形式、預估人數、預算、行政與技術窗口；不重新開放已核定的課程核心與評量政策 |
| T-10～8 週 | 教學團隊與責任 | 講師、助教、替補、教材維護、技術支援與行政分工；確認各角色使用正確文件入口 |
| T-8～6 週 | 交付映射確認 | 將現行 Unit／Lesson 與中文班 4 × 3 小時、英文班 5 × 2 小時的實際課表對齊；保留緩衝與補救時間 |
| T-6～4 週 | 教材與範例驗證 | 雙語教材抽查、連結與導航、GCC／Clang 或指定工具鏈驗證、缺陷案例安全邊界、離線／備援材料 |
| T-4～3 週 | 學生支援準備 | 課前通知、必要設備／軟體、先備與語言支援、可近用性需求；只蒐集教學所需最少資訊 |
| T-3～2 週 | 試教與修訂 | 以真實授課節奏檢查理解負荷、技術契約、雙語等值、常見誤解與備援活動；修正對應的現行雙語文件 |
| T-2～1 週 | 發布前確認 | 教室／會議資訊、帳號／權限、學生入口、教師指引、CI 狀態、工具鏈版本、緊急與離線備援 |
| T | 正式開課 | 執行現行教學與評量政策、提供多元參與方式、記錄需要修正的教材／技術問題；不以出席或工具使用本身代表能力 |
| T+1 週 | 教學檢討 | 彙整可重現的教材問題、技術失敗、雙語落差與學生理解阻塞；必要政策問題回到權威來源處理 |
| T+2～4 週 | 維護收尾 | 將已確認的修正同步到雙語 pair、更新驗證／CI 與 active audit，並把未驗證想法保留為改善候選而非正式要求 |

## 排程變更原則

- 若時數或行政條件改變，先調整節奏、活動切分、緩衝與支架，不應靜默降低核心能力或技術深度。
- 中文與英文班可以採不同 Lesson 切分，但核心能力、Unit 核心問題與正式評量期待維持實質等值。
- AI／外部工具活動預設選用；不得因排程方便而把它加入普遍必做路徑。
- 若時間不足，優先保留理解、追蹤、測試、除錯與驗證所需活動，而不是以「講過」取代能力證據。
- 實際日期與場地等行政資訊可在班級發布入口更新，不需要改寫 Constitution 或設計標準。
